# 페이지별 스켈레톤과 도메인 재사용 경계

## Summary

범용 3카드 로딩 화면을 페이지별 골격으로 교체했다. 공통 상태·막대, 문서 카드, 페이지 조합을 분리하고 실제 화면의 헤더·검색·필터·카드 프레임을 재사용한다.

## Changed

- `/docs`, 피드, Web/Mobile, UI/UX, 카테고리 세 단계, 문서 상세에 도메인 골격을 연결했다. 정적 소개·정책 페이지에는 대기를 추가하지 않았다.
- 홈의 문서 조회를 최근 글 영역으로 내려 소개와 주제 탐색이 함께 기다리지 않도록 했다.
- `shared`의 상태·막대, `entities/document`의 글 카드, 각 `widgets`의 배치로 책임을 나눴다. 실제 화면과 검색 패널·필터·허브 헤더·글 카드 열/썸네일·최근 글 프레임·본문 그리드를 공유한다.
- 상위 카테고리 loading 상속과 사용하지 않는 범용 로딩 컴포넌트를 정리했다. 모음의 선택 이름은 정적 정의를 재사용해 로딩 전후 줄바꿈을 맞췄다.
- [기존 로딩 정책](../../architecture/docs-loading-ux-policy.md)과 [로컬 검증 보고서](../../verification/accessibility/2026-10-19-page-skeletons-local.md)를 연결했다.

## Notes

로컬 검증 조건·실패 발견·보완과 최종 결과는 검증 보고서에 기록한다. 시험용 앱 라우트나 인위적인 지연을 만들지 않았다. 브라우저의 골격 좌표 검사는 실제 서버가 보낸 마크업을 테스트 안에서만 고정해 비교하며 production CLS 측정과 구분한다.

구현·검증 시점에는 커밋·푸시·배포하지 않았다. 10-19 후속 요청에 따라 직전 목록 개선과 이번 스켈레톤을 작업별 커밋으로 구분해 푸시·main 대상 PR을 준비한다. 기존 TCP 초안·도식·관련 증거는 게시 승인 전 보존 작업이므로 제외하며, main에 미반영된 기존 원격 안정화·오프라인·스트림 검증 변경도 PR 범위에 명시한다. PR 생성은 병합·운영 검증 완료를 의미하지 않는다.

## Open Questions

빈 결과, 미확정 필터 수, 문서 제목·본문 길이에 따른 높이 차이는 남는다. 전체 페이지 높이를 강제로 고정하지 않으며 운영 CLS와 실제 느린 연결의 관측이 필요하다.
