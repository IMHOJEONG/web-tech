# 보존 중이던 블로그 작업의 단위별 커밋 준비

## Summary

2026-10-15에 사용자 요청으로 feature/docs HEAD `f064424`에 남은 미커밋 파일 130개를 검토하고 작업별 커밋·푸시를 준비했다. 사용자가 TCP 소켓 초안과 도식의 커밋·푸시를 명시적으로 승인했으며 `status: draft`는 유지한다. main 병합이나 새 글 공개 승인은 이번 요청에 포함하지 않는다.

## Changed

커밋 단위는 다음 일곱 가지다. 공유 목차·TODO·기고 절차는 관련 단위의 내용만 부분 스테이징하고, 마지막에는 원래 작업 트리의 전체 내용과 대조한다.

1. development 전용 draft 미리보기와 파서·스타일·테스트.
2. 저장소 테스트 목록·IDE 가이드·원문 검증 규칙과 HTTP 기고 이력.
3. draft TCP 글·도식과 TCP/이벤트 루프 학습·관측 자료.
4. 코드 접기·큰 기본 글자 헤더의 배포 후 접근성 증거.
5. HTTP 글 게시와 모바일 제목의 Production 확인 기록.
6. 문서 인덱스의 목록 도달 거리 기준선·개선 설계.
7. 주간 게시 글 점검과 초안 점검의 과거 기록.

초안은 공개 목록·검색·sitemap에서 제외하는 기존 계약을 유지한다. 생산 환경에서는 새 preview 경로로 draft를 조회할 수 없다. 개발 서버를 새로 띄우거나 NAS·운영 콘텐츠·기존 자동 실행을 변경하지 않는다.

## Notes

- 원본 130개 파일을 로컬 임시 tar.gz에 백업하고 파일별 SHA-256을 수집했다. 임시 백업은 저장소·커밋에 포함하지 않는다.
- 파일명·크기·링크를 확인했다. 명백한 private key·긴 literal Bearer·GitHub token·비밀번호 포함 URL 패턴은 발견되지 않았고, 새 증거 81개 중 1MiB 초과 파일은 없다. 이 검사는 모든 비밀정보 부재를 보증하지 않는다. 대표 도식·TCP/CPU 관측 화면·모바일 초안 화면도 눈으로 확인했다.
- 필요한 파일만 Prettier로 포맷했다. JSON 11개는 원본과 파싱 값이 같고 초안의 코드 블록 7개는 문자열까지 같다. 기존 MDX data-wip는 수정하지 않았다. 백업 archive의 대괄호 경로가 tar 패턴으로 해석된 비교 실패는 변경된 파일만 hash로 선별해 읽는 방식으로 수정했다.
- Node 24.12.0에서 `pnpm --filter docs test:lib`의 타입·단위 검사 229개, `pnpm --filter docs typecheck`, `pnpm --filter docs lint`가 통과했다.
- 연결된 로컬 실험실에서 `mise exec -- node --test scripts/socket-article-source.test.mts` 11개가 통과했다. 실제 MDX와 fixture의 코드 일치·strict 타입·각 3회 소켓 관측·음성 검사를 포함한다. 관리자 패킷 캡처·NAS·기존 브라우저 측정을 재실행하지 않았다.
- 10-08~14의 보고서와 초기 실패 artifact는 당시 날짜·환경·미검증 범위를 유지한다. 과거 문서의 미커밋 표기는 당시 이력이며 이번 커밋 여부로 덮어쓰지 않는다.
- 각 커밋에서 포맷·문서 구조·연결·크기 검사와 commitlint를 적용한다. 구조·공개 계약의 새 결정은 없으므로 별도 ADR을 작성하지 않는다.

## Open Questions

초안의 커밋 승인은 published 전환 승인이 아니다. main 병합과 새 커밋 SHA의 원격 CI·배포 검증도 각각 구분한다. 과거 측정 파일의 등록이 현재 운영 상태를 재검증한 것은 아니다.

## Next

일곱 커밋을 완료한 뒤 원격 변경과 충돌이 없으면 feature/docs에 정상 푸시한다. CI 결과를 확인하고 실패 시 원인을 분리한다. main은 직접 변경하지 않으며 PR 병합은 별도다.
