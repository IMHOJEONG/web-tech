# 큰 기본 글자 설정의 헤더 보완

## Summary

기본 글자 32px에서 브랜드 링크와 검색 버튼 클릭 영역이 겹치던 모바일 헤더를 보완했다. 글자 확대를 유지하고 공간이 부족하면 두 줄로 배치한다. 로컬 검증 후 `d8c0952`를 푸시했고 CI·Vercel 배포가 완료됐다. 운영 헤더의 핵심 확대 조건은 통과했지만 전체 탐색에는 load 지연이 남았다.

## Changed

- 메뉴·브랜드·도구를 grid 영역으로 분리하고 `20rem` 미만 컨테이너에서 두 줄로 배치한다. 기본 크기의 한 줄 디자인은 유지한다.
- `HeaderFrame`으로 높이 계측 책임만 분리했다. 서버 헤더 구성은 유지하고 본문 바로가기·MDX 제목·고정 목차의 offset에 실제 높이를 공유한다.
- TypeScript E2E에 root 글자 확대 및 격리 브라우저 기본 글자 검사·측정 JSON 첨부를 추가했다.
- [반응형 정책](../../architecture/docs-responsive-policy.md)과 [검증 보고서](../../verification/accessibility/2026-10-11-header-font-preference.md)에 기준·재현 명령·한계를 기록했다. 기존 ADR-0004의 전역 셸 재사용 결정은 유지하므로 새 ADR은 만들지 않았다.

## Notes

중단 후 검사에는 시간 초과가 있었으며 최종 재실행에서 모든 관련 검사가 통과했다. 상세 결과는 검증 보고서에 분리했다. HTTP/TCP 초안과 다른 작업 기록은 유지하고 이 작업의 변경만 부분 스테이징한다.

배포 후 native 기본 글자 12개 조건과 두 언어 root 확대 검사는 분리 실행으로 통과했다. 전체 운영 sweep의 실패와 pending JS/폰트 관측도 숨기지 않고 검증 보고서에 남겼다. 이번 푸시에는 앞서 커밋한 구현·로컬 검증만 포함됐으며 이 후속 배포 기록은 아직 미커밋이다.

## Open Questions

실기기·다른 브라우저와 큰 글자/작은 화면 높이에서의 사용성은 추가 확인이 필요하다.

## Next

운영 정적 JS·폰트 전송 지연을 다른 브라우저/네트워크에서 대조한 뒤 전체 탐색 검사를 다시 수행한다. 후속 배포 기록은 별도 검토 후 커밋한다.
