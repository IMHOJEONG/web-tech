# 코드 접기 배포 후속 점검

## Summary

`9c84c9d`의 CI와 Vercel 배포 완료 후 공개 글의 코드 블록을 검사했다. 코드 조작은 배포 표본에서 통과했고, 별도 전체 화면 점검에서 글자 확대 시 모바일 헤더 겹침을 발견했다.

## Changed

- [기존 검증 보고서](../../verification/accessibility/2026-10-10-code-block-usability.md#2026-10-11-배포-후속-확인)에 CI·배포와 24개 조건 결과를 추가했다.
- 검증 JSON과 헤더 캡처를 보관하고 기존 검증·증거 목차를 갱신했다.
- 애플리케이션 코드·배포 설정·기존 HTTP/TCP 초안 작업은 수정하지 않았다. 새 ADR 결정도 없다.

## Notes

배포의 Chromium 클립보드는 mock하지 않았다. root 글자 크기 변경은 실제 browser zoom이 아니다. 실제 브라우저 제어 도구가 초기화 오류로 실행되지 않아 메뉴 확대·축소와 실기기는 확인하지 못했다. 코드 블록 표본 성공과 서버 스트림 오류 8회, 확대 헤더 문제는 구분하여 보고서에 남겼다.

사용자의 실제 화면 재확인 요청에 따라 기본 크기 10개 조건과 root 글자 200%의 모바일 4개 조건을 비교했다. 기본 크기는 겹침이 없고 확대된 320/390px에서는 두 언어 모두 겹친다. 별도 실제 Chrome 경로는 Apple Events JavaScript 비활성 및 화면 캡처 실패로 검증하지 못했으며 보안·권한 설정을 켜지 않았다. 헤더 비교 측정값과 작은 캡처를 같은 보고서에 추가했다.

후속으로 격리 Chromium의 브라우저 자체 zoom·축소와 실제 기본 글자 설정을 대조했다. CSS root 변경 없이 페이지 확대는 통과했고, 큰 기본 글자에서는 좁은 헤더의 클릭 영역 충돌을 관측했다. 배율 API와 실제 CSS 표시 폭, 초기 창의 최소 폭 제약도 확인했다. 측정값·재캡처와 한계는 기존 보고서에 추가했다.

## Open Questions

헤더의 로고·검색·언어 버튼을 좁은 화면의 글자 확대에서도 겹치지 않게 구성해야 한다. production CI의 스트림 조기 종료는 개별 요청의 취소·장애 판정 증거가 부족하다.

## Next

큰 기본 글자 설정의 헤더 클릭 영역 배분을 보완하고 설치 브라우저 메뉴 조작·실기기를 확인한다. 400%에서 고정 탐색 영역이 차지하는 읽기 공간도 검토한다. 원격 문서 표본과 운영 요청별 스트림 종료 대조도 후속 범위다. 이번 결과는 커밋·푸시하지 않았다.
