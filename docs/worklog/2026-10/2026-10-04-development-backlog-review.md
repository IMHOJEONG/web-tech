# 개발 개선과 기능 추가 백로그 정리

## Summary

docs·NAS·공용 UI를 중심으로 현재 코드와 검증 기록을 대조해 [TODO](../../todo/todo.md)에 실행 우선순위와 완료 기준을 정리했다. vuln-radar는 후속 점검 범위를 분리했으며 전체 기능 감사로 간주하지 않는다.

## Changed

- 최근 검색 캐시·푸시·성능 계측·OG/구조화 데이터 구현과 남은 운영 검증을 구분했다.
- NAS 한 대 기준으로 실제 게시 갱신·외부 백업·격리 복원과 발행 결과 확인 도구를 우선했다.
- 사용자 기능과 공용 패키지·다른 앱의 과제, 측정 후 판단할 보류 항목을 정리했다.
- 공용 본문 검증의 오래된 미완료 표현과 성능 계측 도입 표현, [ADR 색인](../../architecture/README.md)의 Vercel 미배포 표현을 갱신했다.

## Notes

기존 미커밋 V8 글·복구 정책·배포 검증 기록을 유지했다. 코드 확인 대상은 docs-backend 본문 검증·push 저장소, docs 캐시·웹훅·계측, 공용 UI package 설정, vuln-radar scheduler와 테스트 파일 존재 여부다. NAS·Dashboard·브라우저 신규 검증은 실행하지 않았다. `pnpm validate:docs`, 이번 변경 4개 문서의 `prettier --check`, `git diff --check`를 통과했다. 문서 검사는 기존 문제의 증가 여부를 검사하며 기존 문제 전체 해결을 의미하지 않는다.

## Open Questions

NAS 테스트 문서 접근 경로와 외부 백업 목적지, 실제 기기 검증 범위, 공용 UI의 외부 소비 저장소가 필요하다. 기존 세부 TODO 일부는 과거 시안·학습 체크리스트이므로 각 작업 착수 때 실제 코드와 다시 대조한다.

## Next

NAS 연결이 준비되면 게시 V1/V2·원복을 검증한다. 연결 준비 중에는 발행 결과 검사 도구와 실기기·브라우저 검사 중 실행 가능한 항목을 진행한다. 기능 추가 순서는 푸시 실수신 검증, 게시 알림, 콘텐츠 탐색 확장이다.
