# 블로그 UI 조사와 전면 개선안 검토

## Summary

운영 블로그의 데스크톱·모바일을 읽기 전용 점검하고 2026년 공식 디자인 사례를 조사했다. 새 기능·브랜드 교체보다 글의 탐색·판단·독서 흐름을 우선하는 제안으로 정리했다. 앱 구현·배포는 변경하지 않았다.

## Changed

- [설계안](../../architecture/docs-blog-redesign-proposal.md): 페이지별 위계, 조판 초안, 재사용 경계, 적용 순서와 독자 검증 계획.
- [검증 보고서](../../verification/accessibility/2026-10-31-blog-ui-review.md): 운영 8개 URL의 16회 관측과 별도 검색/장문 점검. 관측·추론·미검증 구분.
- 역할별·월별 목차에 이번 문서를 연결했다. 기존 정책·ADR을 대체하지 않았다.
- 대화에서 비교할 글 중심 저널·주제 중심 색인 제안은 저장소 밖에 작성했다. 실제 앱 화면이나 Figma 구현물로 취급하지 않는다.

## Notes

- 추적: [KAN-56](https://web-tech-service.atlassian.net/browse/KAN-56), [Confluence 운영 안내](https://web-tech-service.atlassian.net/wiki/spaces/~5d12f74be69c1c0c88af2afa/pages/65817).
- 원본 checkout의 branch/HEAD/stash와 미커밋 파일은 보존하고 main 기준 별도 worktree에서 문서만 작성했다. NAS 자동화 작업도 변경하지 않았다.
- 원시 캡처·전체 JSON·probe는 저장소 밖에서 유지한다. 공개 업로드 승인 manifest를 임의로 만들지 않고 커밋·푸시·PR을 생성하지 않았다.
- 문서 구조·링크·포맷 및 비교 화면의 좁은 폭 동작은 로컬 검사 대상으로 삼았다. 실제 실행 결과는 아래 최종 검사 항목에 기록한다.

### 최종 검사

- 저장소 `validate()`를 작업 트리 어댑터로 호출해 이번 변경 6개와 문서 링크·목차·필수 절을 검사했고 새 오류 0개였다. stage/커밋 없이 검사한 것이며 `pnpm validate:docs --staged`를 실행했다고 표시하지 않는다.
- 변경 Markdown 6개의 명시적 Prettier 포맷과 최종 check를 수행했다. 전체 저장소 포맷은 하지 않았다.
- 제안 화면 두 종류를 320/390/1024px에서 확인했다. 가로 overflow 0, pageerror 0, 예시 Web 필터·일치 없음 검색은 통과했다. 대화 호스트의 시안 선택 동작·실제 앱 라우팅·다크모드는 이 로컬 검사 대상이 아니다.
- 원본 checkout의 branch/HEAD/stash가 그대로이며 기존 변경 4개 모두 bytes가 동일함을 별도로 확인했다. 운영 화면 관측을 앱 자동 테스트 전체 통과로 표시하지 않는다.
- Jira KAN-56을 검토 중으로 전환하고 3열 표 댓글을 저장했다. Confluence 초안은 재조회 후 재시도했으나 두 번 모두 `snapshot_stale`로 거절됐다. 타 작업의 미게시 변경이나 공개 페이지를 덮어쓰지 않고 기록 대기로 남겼다.

## Open Questions

- 상위 메뉴의 모든 글·실제 게시 주제 노출과 모바일 하단 바 유지 여부는 사용자 검토가 필요하다.
- 제안 시안의 선호와 실제 독자 과제 성공률은 아직 측정하지 않았다.
- Confluence 기록은 기존 미게시 초안과 공개 페이지를 구분하며 원시 캡처는 첨부하지 않는다. 저장 충돌이 해소되면 KAN-56의 짧은 설계 검토 요약만 같은 안내 페이지에 다시 연결한다.

## Next
