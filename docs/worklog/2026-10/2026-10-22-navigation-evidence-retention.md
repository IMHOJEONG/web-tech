# KAN-22 CI 증거 보관과 이동 계측

## Summary

기존 CI에서 사라지던 문서 이동 증거를 JSON/HTML·실패 trace로 보관하고, busy 변화와 응답 수신 완료를 분리한다. 사용자 승인 범위는 구현·로컬 회귀·문서화이며 이번 변경의 커밋·푸시는 아직 하지 않았다.

위와 아래의 미커밋·미푸시·원격 미검증 표기는 최초 로컬 검사 시점의 기록이다. 후속 사용자 승인으로 계측·회귀, CI 보관·격리 probe, 문서·증거를 작업별 커밋으로 나눠 기존 PR #53에 푸시하고 새 head의 원격 업로드·다운로드를 검증한다. 최종 실행 ID·artifact ID·만료일·해시는 PR·KAN-22·Confluence에 연결하며 이전 head의 CI 성공으로 대신하지 않는다. main 병합·운영 배포는 이번 범위가 아니다.

계측·회귀는 `f766855`, CI 보관·격리 probe는 `da27f60`으로 커밋했다. 문서·증거는 세 번째 커밋으로 분리한다. 새 probe의 타입/lint·설정 회귀와 정상 보관 검사를 통과했고 브라우저 실행 실패 대조군은 올바르게 거부했다. 원격 결과는 이 세 커밋을 푸시한 최종 head에 대해 재조회한다.

## Changed

- 오프라인 reporter와 CI artifact 업로드를 연결했다. 공식 action v7.0.2의 SHA를 고정하고 7일 보관·실패 후 실행·결과 경로 allowlist를 사용한다.
- 관측기를 별도 모듈로 분리하고 요청 ID·헤더/본문 수신·pending·busy 변화·문서 교체를 기록한다. HTTP 오류·URL·본문·동일 문서 판정은 유지한다.
- 새 계측 6종×두 화면 회귀와 CI 설정 계약 검사를 추가했다. 긴 결과와 한계는 [검증 보고서](../../verification/resilience/2026-10-22-navigation-evidence-retention.md)에 유지한다.
- 원격 trace 보관 확인용 fixture를 일반 회귀와 별도 경로로 격리했다. harness는 정확히 한 번의 지정 실패·새 JSON/HTML·이동 첨부·유효 ZIP을 요구하며 다른 실패는 CI 실패로 처리한다. 실행 전 자신의 이전 출력만 지워 오래된 증거로 통과하지 않는다.

## Notes

전체 오프라인 34개·계측 반복 36개·저장소 64개와 타입/lint를 통과했다. 임시 의도적 실패는 예상 exit 1로 끝났고 JSON/HTML·이동 첨부와 trace ZIP 생성·무결성을 확인했다. 실패용 테스트와 5.5MB trace를 Git에 넣지 않고 선별 증거·해시만 보관한다. 실제 Next 캐시·환경·기존 stash·TCP 작업은 보존했다. 테스트 관측·기존 증거 정책의 보완이며 새 앱 구조나 공개 계약 결정이 아니므로 ADR을 추가하지 않는다.

Jira KAN-22의 기존 댓글 `10011`에 3열 후속 표를 추가하고 총 7개 표·이전 본문 보존을 재조회했다. Confluence 착수 재조회는 한 차례 도구 오류로 실패했지만 마감 재시도에서 최신 v36을 읽고 v37로 갱신·재조회했다. 다른 작업 KAN-23과 기존 전체 본문을 보존했다. 새 변경은 미커밋이므로 원격 문서 permalink를 만들지 않았으며 Jira 검토 중을 유지한다.
