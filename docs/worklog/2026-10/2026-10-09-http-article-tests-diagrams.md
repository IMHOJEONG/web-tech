# HTTP 기고 원문 테스트와 설명 도식 보강

## Summary

HTTP 초안을 기술·독자·존댓말 세 에이전트로 다시 검토하고,
정식 테스트 및 원문 연결과 정상·취소 도식을 추가했다.
공개 글의 로컬 테스트 저장소 참조를 제거했다. 글은 draft이며 커밋·푸시하지 않았다.

  서버와 클라이언트를 나눈 정상·취소 흐름 도식을 추가했다.
  헤더 확정과 실제 전송을 구분하고 용어·어투와 반복을 다듬었다.

- 수요일 오전 9시 기존 자동 실행 `heapforge-2`에 같은 요구를 추가했다.
  일정과 사용자 초안 검토·게시 승인 조건은 유지했다.

## Notes

- 실험실의 전용 타입 검사 및 전체 `tsc --noEmit` 통과.
  `node:test` 16개(상위 4개와 세부 12개) 통과, 실패·건너뛰기 없음.
  HTTP 실제 실행은 streaming·buffered·cancel 각 3회와 MDX 원문 3회다.
- 정식 실행 원본과 원문 SHA256은 로컬 실험실의
  `docs/verification/2026-10-09-formal-http-tests.md` 및 연결 artifact에서 관리한다.
  서비스 저장소에 테스트 실행 원본을 복제하지 않았다.
- 앱의 MDX 평가기와 CSS로 독립 HTML을 생성해 Chromium에서 도식 두 개를
  1280px/390px, light/dark 조합으로 검사했다. 각 도식 6단계,
  데스크톱 2열·모바일 1열, 내부 넘침과 중첩 p 부재를 확인했다.
  데스크톱 정상/모바일 취소 스크린샷도 눈으로 확인했다.
  [도식 레이아웃 검사 결과](../../verification/artifacts/2026-10-09-http-diagram-layout.json).
- 이 화면 검사는 독립 렌더러와 CSS의 검사이며 실제 Next route나 배포 검증이 아니다.
  초안의 공개 상태를 바꾸지 않았다.
- 기술 검토에서 원문 테스트 누락과 헤더 경계 표현을 지적해 반영했다.
  독자 검토에서 상태 코드와 본문 수신 구분, 반복 및 조사 오류를 수정했다.
  어투 검토에서 타임아웃·Buffer 등의 설명을 보강했다.
- CSS는 이 도식에만 적용되는 표현 변경이다. 구조·공개 계약·공용 컴포넌트
  책임 변경은 없어 새 ADR은 추가하지 않았다. 다른 보안·브랜치 작업의 변경은 포함하지 않았다.

## 후속 초안 보강

2026-10-09 운영·보안·동기화 기록의 선별 커밋을 feature/docs에 푸시한 뒤,
사용자가 선택한 기존 HTTP 초안을 보강했다. 이 후속 작업은 로컬 전용이며
원문·스타일·실험실·이 기록을 스테이징하거나 푸시하지 않는다.

- 기술·독자 검토에서 지적한 비교 실습의 헤더 조건을 통일했다. 두 파일 모두
  `flushHeaders()`와 300ms 지연을 유지하도록 수정 순서·각 3회 실행 명령을 넣었다.
- 취소 실험에 독립 `.mts` 코드와 실행 명령을 추가했다. 누적 첫 줄 확인,
  서버·클라이언트 close 대기, 미완료 상태·완료 이벤트 부재와 타이머 정리를 검사한다.
- `response.complete`는 HTTP 전체 수신·파싱 완료이며 애플리케이션의 소비량과는
  구분하도록 수정했다. Node.js 공식 HTTP 문서의 정의를 원문 참고 자료에 연결했다.
- 존댓말·문장 검토를 반영하고 코드 증가에 맞춰 예상 읽기 시간을 조정했다.
- 로컬 `article-source.json`은 TS 블록 2개에 바인딩한다. 원문 검사에서 정상·취소
  예제뿐 아니라 독자가 설명대로 수정한 비교 2모드도 각각 strict 타입 검사·3회 실행한다.

저장소 루트에서 `mise exec -- node --test`로 실험실의
`scripts/http-response.test.mts`와 `scripts/article-source.test.mts`를 실행했다.
25개 통과, 실패·건너뛰기 없음. 원문 기반 4모드 12회, 실험실 기존 3모드 9회다.
실행 과정의 pnpm 자동 재설치를 피하기 위해 해당 실행에만
`pnpm_config_verify_deps_before_run=warn`을 사용했다. 훅이나 타입 검사를 생략하지 않았다.
`mise exec -- pnpm exec tsc -p`로 실험실의 `tsconfig.http.json`도 통과했다.

원문 SHA-256은 `63f95b57efdd9987a79184632daf4a9ab9b8c6619bf2effe780bacb524de1ab0`이다.
`mise exec -- pnpm --filter docs validate:content`의 18개 파일 검사도 통과했다.
앱 `renderArticleContent`와 React 정적 마크업으로 현재 원문을 평가해
도식 2개·취소 예제·참고 링크·TOC 11개와 중첩 p/H1 부재를 확인했다.
이는 MDX 평가 검사이며 새로운 실제 브라우저 화면·Next production 경로·배포 검증은 아니다.

보강 후 같은 세 에이전트가 담당 관점으로 재검토했고 수정 구간에서 남은 확실한
기술·독자 재현성·한국어 표현 결함은 찾지 못했다. 에이전트는 읽기 전용 검토이며
위 실행 결과는 주 작업에서 직접 수행한 검사다. 검토 통과는 게시 승인과 다르다.

## Codex 파일 미리보기 대응

사용자가 Codex의 초안 파일 미리보기에서 HTML 도식을 볼 수 없다고 확인했다.
앱 CSS에 의존하던 HTTP 도식을 실제 PNG 두 장으로 교체하고 첫 개념도를
도입 바로 뒤에 배치했다. SVG 편집 원본도 함께 보관한다. 각 PNG는 720px이며
앱에서는 최대 360px로 표시한다. 실행 코드 두 블록은 그대로 보존하면서
전체 코드와 추가 재현 설명을 펼쳐보기로 옮겼다. 필수 설명은 절반 이상 줄였다.

- Markdown 이미지에는 실제 파일을 가리키는 상대 경로를 쓴다.
  [MDX 렌더러](../../../apps/docs/lib/render-article-content.ts)는
  [public 이미지 변환기](../../../apps/docs/lib/rehype-public-images.ts)로
  웹의 `/diagrams/…png` 주소를 만든다. 기존 URL과 public 바깥 경로는 변환하지 않는다.
- 기술·독자·존댓말 검토에서 도식의 이벤트 순서와 속성 주체, 용어를 보강했다.
  `finish`는 전송 경로의 순서에서 분리했다. 정상 코드에서 직접 관측하지 않은
  `complete=true` 표시를 제거하고 취소의 `complete=false` 주체를 명시했다.
- HTTP 테스트 25개와 원문 기반 strict 타입·실행 검사는 통과했다.
  두 코드 블록이 축약 전 사용자 원문과 동일함을 다시 대조했다.
  이미지 경로·실제 PNG 파일 검사 3개, node test 타입 검사, 콘텐츠 18개 검사도 통과했다.
  앱 전체 타입 검사와 수정 렌더러 lint, 인덱스를 변경하지 않는 작업 트리 문서 검사도 통과했다.
  pnpm의 자동 의존성 재설치가 중단된 검사는 기존 설치 도구로 재실행했으며
  해당 명령에만 `pnpm_config_verify_deps_before_run=warn`을 적용했다.
- 실제 앱 MDX 평가기와 CSS의 독립 Chromium 화면에서 이미지 디코딩·해상도,
  1280px/390px와 light/dark, 코드 접기·펼치기, 중첩 p 부재를 확인했다.
  모바일 첫 도식과 완료 비교는 스크린샷으로 확인했다.
  [이미지 미리보기 검사 증거](../../verification/artifacts/2026-10-09-http-article-image-preview.json).
- Codex 앱의 화면 자동 접근은 도구가 차단하여 파일 미리보기 자체를 직접
  관찰하지 못했다. 파일 경로와 독립 렌더링 검증을 실제 Codex UI 확인으로 간주하지 않는다.
  실제 Next route·원격 배포도 이번 검사 범위가 아니다.
- 렌더러의 기존 이미지 처리에 제한적인 경로 변환만 추가했다.
  콘텐츠 제공 구조·데이터 흐름·공개 API 계약은 바뀌지 않아 새 ADR은 추가하지 않았다.
  초안은 draft이며 스테이징·커밋·푸시하지 않았다.

## 서비스·인프라 구조와 코드 분할

사용자 후속 요청으로 로컬 서비스 구조와 운영 인프라 개념도를 추가했다.
로컬 그림은 한 Node.js 프로세스의 클라이언트·서버와 운영체제 TCP 루프백을
분리하고 요청·응답 방향을 표시한다. 운영 그림은 브라우저·선택적 전달 계층·
Next.js 실행 환경·데이터 소스를 구분한다. HeapForge의 실제 배치를 검증한
그림으로 표현하지 않았다. CDN 캐시의 앱 우회와 런타임별 스트림 차이도 설명한다.

- 정상 예제는 5개, 취소 예제는 7개로 나누고 최대 32행으로 만들었다.
  함수·역할 경계에서 끝내며 제목과 코드 안의 순번으로 같은 파일에 이어 붙인다.
  취소 실험은 전체 순서를 보존한 선택형 펼쳐보기로 제공한다.
- 클라이언트 수신·검사·요청을 함수로 추출했다. 정상 실험에도 실패 시 연결 정리를
  추가했다. 설명을 덜 늘리기 위해 이벤트 루프의 별도 설명과 반복 제한 문구를 줄였다.
- 로컬 실험실 바인딩은 `filename`·`part`를 검사하고 5+7개 원문을 두 `.mts`로
  재조립한다. 누락·중복·순서 변경·미등록 조각·전체 개수 불일치와 서버 오류 로그를 검사한다.
- 원문 합본 4모드 strict 타입·각 3회 실행과 기존 fixture를 포함해
  `node:test` 26개·HTTP 실행 21회가 통과했다. 이미지 경로 검사 3개,
  앱 node test 타입 검사와 콘텐츠 18개 검사도 통과했다.
- 실험실 전체 타입 검사에서 `.mts` import 허용 설정 누락을 발견했다.
  `noEmit` 구성에 `allowImportingTsExtensions: true`를 추가하고 재검사해 통과했다.
  실패와 재검사 원본은 실험실의 같은 주제 검증 보고서와 연결 artifact에 보관했다.
- 독립 앱 MDX/CSS 화면에서 그림 4개를 1280px/390px·light/dark로 검사했다.
  720px PNG 로딩·표시 폭·넘침 부재, 원문의 12개 코드와 취소 펼쳐보기 동작을
  확인했다. 로컬·운영 도식은 모바일 스크린샷으로도 확인했다.
  [아키텍처·코드 분할 증거](../../verification/artifacts/2026-10-09-http-architecture-code-parts.json).
- 세 에이전트의 지적을 반영해 요청 헤더 해석과 요청 본문 읽기를 구분하고,
  `ServerResponse`의 Writable API와 직접 상속을 구분했다.
  구조 추가는 공개 글의 교육용 도식이며 서비스 설계 변경이 아니므로 ADR은 추가하지 않았다.
  draft·로컬 검토 상태를 유지하며 커밋·푸시·게시하지 않았다.

## 개발 서버 초안과 제목·도식 배치

사용자가 Codex 파일 미리보기 대신 기존 블로그 개발 서버를 요청했다.
공개 문서 route는 draft를 제외하여 본문이 표시되지 않았다. 개발 환경에서만
로컬 draft를 읽는 `/[locale]/preview/[...slugParts]` 경로를 추가했다.
원격 콘텐츠를 조회하지 않고 실제 앱 MDX 컴포넌트와 상세 레이아웃을 재사용한다.
정규 파일 목록에서만 읽으며 경로 이탈·심볼릭 링크·published·archived를 제외한다.
production/test에서는 초안 조회를 거부하고 preview metadata는 noindex/nofollow다.

- 사용자 제목·그림 크기 지적에 따라 제목을
  `Node.js HTTP 스트리밍: 응답이 도착하는 과정`으로 정리하고 preview H1을 줄였다.
- 네 도식에 가로형 SVG/1600px PNG를 추가했다. 640px 이상에서는 본문 폭을
  사용하고 작은 화면에서는 기존 세로 PNG를 사용한다. 선택은 실제 picture/source로
  구현하며 다른 이미지 렌더링에는 적용하지 않는다.
- 기술·독자·존댓말 에이전트 검토를 수행했다. 작은 보조 글자와 완료 도식의 짧은
  화살표 지적을 반영해 가로 도식 글자와 화살표를 보강했다.
- 실제 기존 Next 개발 서버의 해당 preview에서 1280px·670px·390px를 검사했다.
  새 제목, 네 이미지의 실제 디코딩·선택된 src·표시 폭, 취소 코드 펼쳐보기가 통과했다.
  670px에서는 네 가로 도식이 622px, 390px에서는 세로 도식이 358px로 표시된다.
  제목과 첫 도식 화면도 직접 확인했다.
- node 단위 검사 11개, 앱 전체 타입 검사, 변경 코드 lint, 콘텐츠 18개 검사가 통과했다.
  실제 production build/배포는 검사하지 않았다. 예제 코드는 이전 단계 이후 그대로다.
