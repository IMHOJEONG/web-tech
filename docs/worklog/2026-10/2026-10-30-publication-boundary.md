# 블로그 공개 경계와 업로드 검수

## Summary

사용자 요청에 따라 블로그 업로드의 공개·비공개 경계와 검수 절차를 추가한다. `draft`는 Git 비공개를 보장하지 않으며, 원시 실험 데이터와 비밀값은 저장소 밖에서 관리한다. `28fedc40` 기준 별도 브랜치에서 먼저 로컬 구현·승인 누락 차단을 확인했고, 아래 후속 사용자 승인 범위에서만 커밋·푸시를 준비한다. 실제 글 게시·원격 설정 변경은 별도다.

## Changed

- [ADR-0025](../../architecture/adr-0025-publication-boundary.md)와 [공개 검수 절차](../../process/publication-review.md)에 분류·수동 체크·승인 해시·권한 한계를 정리한다.
- Git 인덱스·푸시할 각 커밋의 blob·메시지·ref를 검사한다. 실제 값·파일명을 출력하지 않고, private 경로·대표 credential 패턴·미게시 글·승인 누락/해시 불일치를 차단한다.
- `.publication-review.json`은 빈 목록으로 도입한다. 기존 글·에셋·증거를 일괄 승인하지 않는다.
- 루트 커밋·푸시 훅과 Documentation CI에 연결한다. offline 증거 생성·검사는 유지하고 원시 artifact 업로드는 명시적 합성 증거 공개 opt-in 없이는 생략한다.
- 블로그 지침의 실제 개인 실험실 경로는 제거하고 비공개 기록을 참조하도록 바꾼다. 과거 Git 이력의 해당 내용까지 지워졌다는 뜻은 아니다.

## Notes

[KAN-53](https://web-tech-service.atlassian.net/browse/KAN-53)에서 추적한다. 기존 파일·stash·원시 보관 자료를 삭제·이동하지 않으며 실제 토큰도 열람·회전하지 않았다. 테스트에는 런타임에 조합한 무효 합성 값만 사용한다.

최초 새 검사 실행은 큰 입력 대조를 보완하기 위해 중단했으며 서비스 장애나 기존 회귀 실패로 해석하지 않는다. 과대 blob은 패턴 검사 전에 거절하고 URL 패턴의 반복 폭을 제한했다.

Node.js 24.22.1·pnpm 12.14.0에서 현재 브랜치의 작업 파일·인덱스를 검증했다. 기준 HEAD는 `28fedc40`이며 새 변경은 아직 커밋하지 않았다.

| 명령                          | 결과와 범위                                                                                                      |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `pnpm test:repo`              | 최종 218/218, fail·skip·cancel 0. 새 공개 경계 회귀 20개 포함                                                    |
| `pnpm typecheck:toolchain`    | 통과. 새 MTS와 테스트를 기존 Node 24 type stripping 조건으로 검사                                                |
| `pnpm format:staged:check`    | 통과. 지원 형식만 읽기 전용 검사, ignore 파일에 포맷 파서를 강제하지 않음                                        |
| `pnpm validate:docs --staged` | 통과. 구조·인덱스·상대 링크 검사                                                                                 |
| `pnpm publication:staged`     | 예상대로 exit 1. 공개 승인이 없는 docs Markdown 6개에만 `public-review-required`, 비밀 패턴 등 다른 finding 없음 |

최초 전체 회귀는 215개 중 213개 통과·기존 소켓 검사 2개가 `127.0.0.1` listen EPERM으로 실패했다. 허용된 환경에서 같은 기준으로 215개를 재실행해 통과한 뒤 추가 회귀까지 포함해 최종 218개를 실행했다. 기대값·보안 검사 기준을 완화하지 않았다. 원시 출력·임시 fixture는 공개 artifact에 추가하지 않는다.

공개 대기 6개는 ADR-0025·공개 검수 절차·이 작업 기록과 각 역할 목차다. 해시 승인 목록은 계속 비어 있다. 이번 도구를 검증하기 위해 실제 정책 자료를 자동 승인하지 않았다. GitHub Actions·NAS·실제 업로드를 새로 실행한 결과로 표현하지 않는다.

## Open Questions

- NAS 콘텐츠 승격·API 검사에는 아직 이 검수 기록이 연결되지 않았다.
- 실제 사용자 승인 신원은 JSON/로컬 훅으로 인증하지 못한다. KAN-33의 권한 분리·보호 설정과 별도로 진행해야 한다.
- 기존 공개 Git·artifact·외부 에셋의 전체 감사, 비공개 증거 저장소와 키 회전은 후속 승인 범위다.

## Next

2026-10-30 사용자가 이번 변경의 커밋·푸시를 요청했다. 공개 범위는 도구·설정·정책 18개 파일이며, 앞서 차단된 6개 문서만 이번 요청의 공개 의도와 최종 bytes에 연결해 검수 기록을 작성한다. 작성한 절차·자가 작성 요약·목차·공식 원문 링크만 포함하며, 원시 데이터·비밀값·제3자 이미지/영상 복제는 포함하지 않는다. 이 승인을 기존 글·초안·원시 보관 자료로 확대하지 않는다.

승인 기록 등록 후 같은 staged 포맷·문서·공개 경계 검사, commitlint와 전체 회귀를 적용한다. 원격 결과는 KAN-53·Confluence·PR에서 커밋 기준으로 확인한다. main 병합·원격 변수 활성화·NAS 적용·실제 블로그 글 승인은 이번 커밋·푸시 요청에 포함하지 않는다.
