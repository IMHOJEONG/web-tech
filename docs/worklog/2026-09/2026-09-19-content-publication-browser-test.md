# 게시 후 목록·검색·상세 갱신 검증

## Summary

캐시 API 응답 검사에 더해, 원본 문서 수정과 revalidation webhook 이후 실제
브라우저 화면의 제목·요약·본문이 함께 갱신되는 테스트를 추가했다.

## Changed

- 기존 article E2E fixture에 별도의 게시 검증 문서와 테스트 전용 버전 변경 endpoint를 추가했다.
- 읽기 토큰과 revalidation 토큰을 구분하고 누락·오인증·읽기 토큰의 401을 검증한다.
- 캐시 TTL을 테스트에서만 3600초로 설정하여 자연 만료에 의한 오탐을 피한다.
- 정상 webhook 후 새로고침, 목록·검색 재접근, 이전 요약 검색 결과 제거를 검사한다.
- [운영 절차](../../runbooks/docs-article-rendering-regression.md#게시-후-화면-갱신)와 기존 캐시 시험 안내를 갱신했다.

## Notes

게시 갱신 4개 조합은 두 번 모두 통과했고 ESLint도 통과했다. 서버의 스트림
조기 종료 로그는 남아 있어 기능 검증 통과와 구분해 기록했다.
실제 NAS, 운영 토큰, Vercel 배포는 사용하지 않는다. 테스트용 변경 endpoint는
loopback fixture에만 존재하며 운영 애플리케이션에는 추가하지 않았다.
검증 결과는 [실행 보고서](../../verification/cache/2026-09-19-content-publication-browser-test.md)에 남긴다.

## Open Questions

실제 배포 환경의 WAF 및 NAS 연결은 별도 운영 검증이 필요하다.
후속 비교에서 prefetch 허용/차단/재허용 시 조기 종료 로그가 2/0/2회로 바뀌었다.
실제 페이지 요청은 세 실행 모두 21건 정상 완료했다. 이번 테스트의 원인은
빠른 페이지 이동에 따른 prefetch 스트림 취소로 판단한다. 요청 ID 기반 서버와
브라우저의 일대일 연계 및 운영 환경 재현은 아직 수행하지 않았다.

## 후속 추적 변경

- `cc954d4`로 부가 영역 스트리밍과 단계별 시간 측정 구현 8개 파일을 먼저 커밋했다. push는 하지 않았다.
- 게시 테스트에 기본 비활성인 요청 추적과 prefetch 대체 실험 옵션을 추가했다.
- 정상 모드에서는 앱과 테스트의 prefetch 동작을 유지하며 서버 오류를 숨기지 않는다.
- 실행 명령과 제한은 위 운영 절차, 관측값은 위 실행 보고서에 추가했다.
