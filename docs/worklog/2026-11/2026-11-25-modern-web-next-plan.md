# Modern Web Guidance 후속 계획 정리

## Summary

사용자 요청대로 HTTPS·WebKit 호환과 정제 검증을 먼저bf316ae1에 로컬 커밋했다. 이어 [후속 실행 계획](../../todo/modern-web-guidance.md)을 작성해 다음 한 주제를 Feed 검색·필터·페이지 상호작용 진단으로 권장한다. 이번 후속은 계획 문서이며 새 제품 코드는 수정하지 않았다.

## Changed

기존 일반 TODO·감사/검증 문서를 먼저 확인했다. 현재 순차 실행 기준을 담은 전용 문서가 없어 docs/todo에 만들고 역할/월 목차를 연결했다. 완료된 이미지·폰트·취소와 보류한 lazy route·content-visibility 실험을 구분했다. 각 후속의 근거·표본 계획·완료 조건·범위와 배포 의존성을 명시했다.

## Notes

Modern Web Guidance의 로컬 identify-inp-causes·identify-heavy-scripts·performance 및 기존 관련 검증을 대조했다. 새로운 원격 스캔·지원표 갱신·필드 INP·운영 CWV 측정은 실행하지 않았다. 검색 debounce·API 대기·이벤트 지연을 분리하고 미지원 값을0으로 보고하지 않도록 계획했다.

기존 지식 문서에 “도입 이득이 없는 실험은 보류하고 다음 관측 대상을 선택한다”는 판단 기준을 보완하며 실행 상태는 KAN-83 표에서 따로 기록한다. 새로운 공개 계약·구조 결정이 없어 ADR은 추가하지 않는다. AGENTS 공통 지침의 로컬/원격 변경 없음·원본51개 보존·VoiceOver 생략·미푸시/미배포다.

마감 시 KAN-83 댓글10127의 실제3열 표·로컬bf316ae1/계획미커밋 상태를 재조회했다. Confluence 지식v43의 본문·근거·로컬 원본 경로와 개요98404→운영 안내65817 탐색 경로, 운영 댓글21626883 v2의 후속3열 표도 재조회했다. 지식 본문과 실행 댓글을 구분한다. web.dev의 INP 진단과 MDN의 supportedEntryTypes 공식 문서를 확인해 계획의 근거로 연결했다. 계획4파일의 포맷·문서 delta는0문제이며 인덱스는 비어 있다. 이 계획은 사용자 요청의 “커밋 후 문서 정리” 단계로 미커밋 상태다.

## Open Questions

성능 병목은 아직 미판정이다. CSP 원격 검증에는 대상 head와 배포 범위 결정이 필요하다. 계획 문서만으로 운영 준비나 개선 효과가 입증되지 않는다.
