## Notes

11-17 최초 기준 통합은 충돌 없이 완료됐으며 원본 JSON6개와 비공개 보관본의 bytes가 일치했다. 예제 타입·정상 Brotli 합성 진단·staged 포맷·문서 delta·diff 검사는 통과했다. 최초 loopback EPERM과 동일 코드 재검증을 구분하고, 공개 검사에 탐지된 가짜 DB 자격 증명 예시도 인증 부분 없는 URI로 바꿨다. 공개 승인 요구는 남겨 두고 임의 해시를 등록하지 않았다. 기존 공통 설정·의존성 lockfile·실제 운영 환경은 변경하지 않는다. 구조·공개 계약의 새 결정이 없어 별도 ADR은 만들지 않았다.

11-20에는 새 기준에서 예제 타입·정상 Brotli 진단·후보24개의 읽기 전용 문서 검사·포맷·diff를 재검증했다. 정제 JSON6개는 허용한 제외 필드 외 역사적 값이 동일했고, 원본 HEAD·index와 main 목차 링크도 유지됐다. 공개 검사는 승인 요구22개만 남았고 새 index는 비어 있다. 세부 조건과 검사 한계는 검증 보고서에 연결하며 원격 CI·운영 재검증 결과로 일반화하지 않는다.

KAN-81의 기존3열 표 댓글10112와 Confluence 진행 댓글18153485(v3)에 정제한 후속 결과만 추가하고 재조회해 본문 보존·표·링크를 확인했다. 이 기록은 로컬 검증에 관한 것으로 새 공개 커밋이나 지식 페이지 생성 완료가 아니다.

## Open Questions

11-20 재구성에서는 목차2개 충돌을 최신 main의 항목을 보존하는 방식으로 해결하고 과거 실제 응답 필드·불필요한 배포 메타를 정제했다. 정상 Brotli 예제3개는 ignore 대상이므로 아직 추적하지 않으며, 정제24개 범위와 함께 실제 공개 승인을 먼저 확인한다. 상세 결과와 원본 보존은 [검증 보고서의 후속 구역](../../verification/integration/2026-11-17-open-records-pr-consolidation.md#2026-11-20-재구성과-공개-경계)을 따른다.

이번 정리는 기존 ADR-0025의 공개 경계를 적용한 이력 보존이며 새 구조·공개 계약 변경이 없다. 새 ADR·지식 페이지를 만들지 않고 Jira·Confluence 진행 기록만 갱신하며 이를 지식 문서화 완료로 보고하지 않는다.

통합본의 정제 문서와 집계도 사용자 공개 검수와 정확한 해시 승인 전에는 푸시할 수 없다. #66의 미반영 코드 및 #75의 신원 분리는 이 기록 통합만으로 완료되지 않는다.

후속 사용자 승인은 이번 후보24개와 해당 검수 해시를 작업별 로컬 커밋하는 범위다. 예제3개만 개별 추적하며 기존 ignore와 검사 규칙은 유지한다. 실행 코드·타입 설정과 정제 기록을 분리하고, 공개·포맷·문서 검사를 실제 index와 새 이력에 다시 적용한다. 앞의 미승인·미커밋 문장은 재구성 검사 시점의 기록이다. 푸시·새 PR·기존 PR 종료·병합·배포는 계속 제외한다.

첫 로컬 커밋 `ab9257ff`는 합성 진단 실행 코드·타입 설정2개다. 실제 pre-commit의 staged 포맷·문서·공개 검사와 commit-msg 검사·commitlint가 통과했다. 나머지 예제 설명·정제 기록22개는 승인된 최종 bytes의 해시와 함께 분리하며 같은 훅과 `pnpm publication:check --base 2cf837f04954d05d5ff409bdec6794ec28fd7f07`로 두 커밋의 범위를 확인한다. 새 커밋의 검사 결과는 같은 Jira 댓글에서 로컬-only로 추적한다.

11-17 최초 준비 후 보안 PR #95(`6b807f26`)가 반영돼 기존 `3b5444ed` 기준의 재통합이 필요했다. 11-20 새 main 재구성으로 그 대조를 수행했으며, 당시 원본 stage는 덮어쓰지 않았다. 이후 새 main 변경이 생기면 공개·커밋 전에 다시 대조해야 한다.
