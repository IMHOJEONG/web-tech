# 게시 revision·캐시 세대 로컬 실험

## Summary

revision은 콘텐츠 식별자, 세대는 게시 작업의 캐시 격리 경계라는 차이를 정리하고
기존 지연 순서에서 새 요청 B의 V2 필수 조건을 실제 Next 상세 렌더링으로 검사했다.
운영 적용이 아니라 로컬 설계 실험이다.

## Changed

- 기준 로컬 커밋은 `978eae792468790ea1fba75afb0f1f085b0f1954`이며 앞선 두 커밋을 변경하지 않았다.
- 요청 시작 시 lease 고정, 세대별 키 분리, 이전 lease 쓰기 거절과 예상 세대 CAS를 test-only 모델·preload로 분리했다.
- 앱 전용 실험 설정에만 preload를 연결했다. 기존 지연 진단·일반 설정·운영 코드·루트 공통 설정·NAS는 변경하지 않았다.
- 기본 서버에는 실험 제어 경로가 없음을 확인하는 회귀를 추가했다.
- 원본을 새로 게시하지 않은 음성 대조로 세대 번호만으로 실제 revision을 보증할 수 없음을 확인했다.
- [개념 문서](../../knowledge/content-platform/docs-cache-structure.md#revision과-캐시-세대는-무엇이-다른가)를 기존 캐시 지식에 보강하고 [검증 보고서](../../verification/cache/2026-11-06-publication-generation-experiment.md)에 조건·명령·결과를 분리했다.

## Notes

guard 적용 전 B=V2 조건의 예상 실패부터 확인했다. 이후 보호·비보호·음성 대조를 반복했으며
상세 수치는 보고서에만 유지한다. 검사 조건·timeout·retry를 완화하지 않았다.
원시 trace·로그는 저장소 밖에 보관한다. 최초 실험 종료 시에는 공개 검수 해시·stage·커밋·푸시·배포를 수행하지 않았다.
실제 권한·자격 증명·NAS·기존 stash와 다른 작업 트리는 변경하지 않았다.

[KAN-58](https://web-tech-service.atlassian.net/browse/KAN-58?focusedCommentId=10085)과
[Confluence](https://web-tech-service.atlassian.net/wiki/spaces/~5d12f74be69c1c0c88af2afa/pages/65817?focusedCommentId=14581761)에
정제 결과를 갱신하고 실제 3열 표·이전 이력 보존을 재조회했다. 페이지 본문은 변경하지 않았다.

이 실험만으로 운영 캐시 교체를 결정하지 않아 ADR-0011을 대체하지 않는다.
운영 구조를 선택할 때 별도 제안 ADR과 공유 저장소·콘텐츠 계약 검토가 필요하다.

### 같은 날 공개 검수·로컬 커밋 승인

사용자가 이번 실험 코드와 정제 문서만 공개 검수하고 작업별로 커밋하도록 승인했다.
TypeScript 실험·회귀·설정 5개와 개념·검증·작업·목차·TODO 7개를 범위로 확정했다.
자체 작성 코드·합성 입력·정제 집계만 포함하며 실제 비밀값·개인정보·개인 경로·원시 자료와 권리 침해 요소를 검수한다.
최종 문서 7개의 인덱스 bytes와 SHA-256을 대조하고 대응 공개 검수 기록만 갱신한다.
원시 trace·로그·이벤트·녹화본·기존 초안은 제외하고, 뒤이어 작성할 NAS revision 설계는 이 커밋에 섞지 않는다.
푸시·PR·병합·배포·NAS 설정 변경은 수행하지 않는다.
같은 최종 소스의 실험 36개·기본 production 198개와 lint·타입을 재확인하고 코드 5개를
`8e7963d0cb5a80ab2188c9aaa7618320ecc56b4e`로 분리했다. 문서·검수 기록은 별도 커밋으로 관리한다.
