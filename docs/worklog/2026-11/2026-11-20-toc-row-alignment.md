# 목차 항목 텍스트의 세로 중앙 정렬

## Summary

사용자 화면에서 목차 글자가 위쪽에 놓여 보이는 현상을 확인했다. 공개 운영 화면의 모바일·태블릿 한 줄 텍스트 박스가 링크 중앙보다 4px 위에 있었으며, 최소 터치 영역은 유지하고 내용의 세로 정렬만 보완했다. [KAN-72](https://web-tech-service.atlassian.net/browse/KAN-72)의 기존 목차 후속이며, 로컬 검증·사용자 확인 후 이번 변경만 공개 검수·커밋·푸시하도록 승인받았다.

## Changed

- 공통 `TocLinks`의 flex 교차축 정렬을 `items-center`로 변경했다. 높이·padding·색상·계층별 시작선·현재 항목·앵커 처리는 유지했다.
- 기존 목차 E2E에 root 16px·24px의 실제 DOM 박스 중심·최소 높이·동일 계층 시작선·들여쓰기·넘침 검사를 추가했다. timeout/retry와 기존 assertion을 바꾸지 않았다.
- [기존 검증 보고서](../../verification/accessibility/2026-11-14-article-toc-ux.md#2026-11-20-후속-항목-내-텍스트-세로-정렬)에 측정·재현·결과와 한계를 추가했다.

## Notes

기준 main은 `2728665e`이며 다른 작업과 분리한 `codex/docs-toc-alignment-20261120`에서 수정했다. Chromium 390·768·1280px, workers 2·retries 0에서 20개 통과·기존 화면 범위 skip 1개·실패 0개였다. 코드 lint도 통과했다. 합성 입력 생성기의 기존 디렉터리 보호 차단은 그대로 유지하고 필요한 빈 경로 두 곳에만 입력을 생성했다. 완료 후 생성한 bytes와 대조해 해당 두 파일만 정리했다. 설치는 frozen lockfile·ignore-scripts·offline이며 dotenv skill을 승인하지 않았다.

기존 다른 작업의 미커밋·stash·원문·비공개 저장소·키·운영 설정·콘텐츠 lock을 변경하지 않았다. 최초 검증 시에는 공개 검수 해시·stage·커밋·푸시·배포를 하지 않았다. 기존 목차의 표현 보완으로 새 데이터 흐름·공개 계약 결정이 없어 ADR을 추가하지 않는다. 남는 교훈은 최소 터치 높이와 flex 교차축 정렬을 함께 측정해야 한다는 기존 목차 접근성 검증의 보완이며 새 지식 페이지를 만들지 않는다. 실행 기록은 기존 KAN-72·관련 [Confluence 논의](https://web-tech-service.atlassian.net/wiki/pages/viewpage.action?pageId=65817&focusedCommentId=17793025)에 연결한다.

사용자가 합성 문서로 로컬 수정본을 확인한 뒤 서버 종료·커밋·푸시를 요청했다. 3076 포트의 서버가 이번 작업 트리의 프로세스임을 확인해 해당 서버만 종료했고 listen 종료를 재확인했다. 미리보기용으로 다시 생성했던 합성 문서 2개도 생성기의 출력 bytes와 일치함을 확인한 뒤 정리했다. 실제 글을 이전·게시한 작업이 아니다.

공개 승인 범위는 목차 코드·회귀 테스트 2개와 이 worklog·기존 검증 보고서·월별 목차 3개다. 문서 최종 인덱스 bytes를 검수해 승인 목록과 함께 기록하고, 구현/회귀와 정제 문서를 나누어 커밋·푸시한다. 원시 화면·로그·합성 미리보기 파일·다른 작업은 제외한다. 실제 원격 커밋과 전송 결과는 KAN-72·Confluence에 연결하며 공개 성공을 사전에 추정하지 않는다. 최신 원격 main에 다른 작업의 게시 커밋이 추가된 것은 조회만 했고 이번 변경에 섞지 않았다.

커밋 전 재검증에서 docs 전체 타입 검사·변경 코드 lint·포맷이 통과했다. 구현과 회귀 2개는 `d060389fdd1e309c967af2e686a5347b49395e77`에 먼저 기록했고 문서·검수 목록은 별도 커밋으로 분리한다. 로컬 훅·commitlint·공개 전송 범위 검사를 유지한다.
