# 비공개 Git 콘텐츠 공급 경로 구현

## Summary

공개 서비스 코드와 비공개 원문을 분리하는 사용자 요청으로 KAN-80을 이어서 작업했다. 기존 Preview 구현을 확인하고 main 기반 별도 브랜치에서 빌드 전용 Git 공급·공개 검수·NAS 차단을 보완했다. 운영 전환이나 공개 원문 삭제는 아직 하지 않았다.

## Changed

- 모드·리비전·파일 root·검색 digest·Next trace와 빌드 진입점을 연결했다.
- 고정 SHA·발행 URL 집합·파일별 공개 검수·작성 규칙·참조 자산과 상한을 검증한다. Git은 외부 임시 bare 디렉터리에서 읽고 키를 정리한다.
- private Git 모드의 목록·검색·본문 누락이 NAS로 fallback하지 않게 했다. 기존 legacy 모드는 보존했다.
- 빌드 공급 경로와 합성 회귀, [설계](../../architecture/adr-0032-private-git-build-content.md), [운영 절차](../../runbooks/docs-private-git-content.md), [검증 결과](../../verification/content/2026-11-17-private-git-content.md)를 추가했다.
- 기존 CLI 테스트의 파일 URL 디코딩과 validator fixture의 새 의존성을 보완했다. 기준·timeout·retry는 변경하지 않았다.

## Notes

기존 콘텐츠 저장소의 17개 글·15개 자산은 main과 동일했다. 사용자 승인으로 이 기존 공개 파일만 재검수해 로컬 승인 목록을 저장소 밖에 만들었다. 원시 자료·추가 글·PNA·공개 저장소 실제 승인 목록·원격 Git은 변경하지 않았다. 이전 KAN-80 Preview 결과를 이번 로컬 구현의 배포 결과로 재사용하지 않았다.

구체적인 실행 결과와 실패는 검증 보고서를 따른다. 기존 다른 작업 트리·stash는 보존한다. 공개 검수·커밋·푸시·Production·NAS·토큰 변경은 이번 구현 완료와 구분한다.

최종 콘텐츠·라이브러리·저장소 검사와 격리 출력물의 한·영 상세/탐색·NAS 0회 검증을 마쳤다. Next 빌드는 설치된 버전의 보안 종료 때문에 exit 1이므로 배포 준비 완료로 표시하지 않는다. 로컬 검증 서버는 이번 작업에서 시작한 프로세스만 종료한다.

## 보안 패치 병합 후 재개

사용자 승인으로 PR #96을 최종 메시지 사전검사 후 main `a7e095c5adf3eee214e741ed259a048a78ffe712`에 병합했다. 콘텐츠 전환 브랜치도 새 main까지 fast-forward했다. 목차 2개만 임시 보관·양쪽 내용 병합 후 원래 unstaged 상태로 복원했고, 소스 등 나머지 27개 변경의 해시와 기존 stash 10개를 확인했다. 추가 조사 브랜치의 미커밋 3개와 원래 작업 트리의 기록은 별도로 보존했다.

전환 코드가 포함된 표준 빌드와 로컬 private-git 출력 빌드가 Next 16.4.6에서 모두 exit 0으로 끝났다. 실제 승인 원문 준비와 콘텐츠 47개 회귀도 통과했다. SecurityFatalError 차단은 해소됐으며 앞선 실패 기록은 지우지 않았다. [통합 검증 결과](../../verification/content/2026-11-17-private-git-content.md#pr-96-병합-후-통합-검증)에 원격 main CI·Production·공개 GET과 전환 미배포 범위를 구분해 기록했다.

남은 작업은 비공개 검수 목록의 실제 커밋·리비전 갱신, PNA와 게시 URL 대조, 인증된 Preview다. 이번에는 기존 승인 범위인 로컬 검증까지만 수행했고 콘텐츠 저장소 푸시·운영 콘텐츠 전환·NAS 변경은 하지 않았다.

## 2026-11-18 보호된 Preview까지 재개

사용자 승인으로 기존 공개 파일 32개의 검수 목록 한 파일만 비공개 저장소에 커밋·푸시했다. 원문·자산은 그대로이며 앱 lock을 새 리비전 `8e53eab`로 고정했다. 기존 키로 실제 읽기 전용 Git fetch를 수행하고, 원본 작업 트리와 분리한 사본을 CLI로 Preview 배포했다. 공개 코드 커밋·푸시·PR·운영 도메인 승격은 하지 않았다.

[인증된 Preview 결과](../../verification/content/2026-11-17-private-git-content.md#2026-11-18-인증된-preview-검증)에 배포 식별자와 한·영 전체 목록·본문 검색·실제 상세·자산·브라우저 Link 여정, 중간 실패와 보완을 구분해 기록했다. Preview 빌드와 콘텐츠 47개·라이브러리 373개가 통과했다. 기존 보호 설정·Production·영구 환경 변수는 유지했으며 원시 로그·화면·인증 값은 공개하지 않았다.

절차에는 격리 사본의 workspace/type 입력 보존과 동일 origin에만 인증을 전달하는 검증 방식을 보완했다. ADR-0032의 적용 범위도 Preview까지로 갱신했다. 기존 미커밋은 의도한 lock·문서 보완 외에 보존하고 인덱스·stash는 변경하지 않는다.

다음은 사용자 검토 후 운영 전환 여부를 결정하는 것이다. PNA·다른 NAS 전용 원문과 외부 자산의 누락, 공개 원문 제거 후 합성 CI와 인증된 콘텐츠 빌드의 분리, 콘텐츠 승인·lock 갱신·rollback 운영 절차는 전환 전 남은 조건이다. 이번 Preview의 성공을 이 조건들이 모두 해소됐다는 의미로 쓰지 않는다.

## 2026-11-19 운영 전환 승인 후 분리

사용자는 기존 승인된 17개 글·15개 자산을 별도 PR로 공개 검수·검증·병합한 뒤 Production으로 전환하도록 승인했다. NAS 전용 글은 수동 이전이며 공개 원문·과거 이력·NAS는 삭제하지 않는다. 인증 CI 보호 Environment와 별도 실행/승인 신원은 후속 과제로 유지하고 승인된 main의 Vercel 빌드로 검증한다.

PR #97을 최종 메시지 사전검사 뒤 main `84c89d20`으로 병합하고 새 브랜치로 로더·회귀·설정·정제 문서를 분리했다. 기존 39개 미커밋 작업 트리의 bytes·HEAD·인덱스·stash는 수정하지 않고 CI의 오래된 사본도 제외했다. 새 브랜치에서 콘텐츠 47개·lib 373개·저장소 276개, 앱 타입·lint, 고정 발행본 준비와 키 없는 production 상세 34개 검증을 통과했다. [실행 조건·실패·한계](../../verification/content/2026-11-17-private-git-content.md#2026-11-19-운영-전환-pr-준비)는 보고서에 연결한다.

기본 legacy는 유지한다. 별도 PR의 CI·리뷰 후 병합하고, Production 키 범위·고정 main SHA·후보 검증·도메인 전환·이전 정상 배포 복구 순서를 확인한다. 실제 Vercel 변수·도메인 전환은 아직 미실행이다. 원시 자료는 제외하고 사용자 승인한 코드·정제 문서·검수 해시만 작업별 커밋으로 준비한다.

[배포 식별자·명령 기준·결과·한계](../../verification/content/2026-11-17-private-git-content.md#2026-11-19-production-전환-완료)는 보고서를 따른다.

## 운영 후속 기록의 커밋 분리

사용자가 공개 사본 정리와 관련 운영·검증 기록의 작업별 커밋을 승인했다. 위 운영 완료 후 로컬 기록 3개를 최신 main 기반 새 브랜치로 복사하고 ADR 적용 상태와 설계 목차를 함께 정리한다. 원래 미커밋 사본은 덮어쓰지 않으며, 이전 시점에 로컬-only였다는 기록도 보존한다. 이번 기록 커밋을 추가 운영 배포나 공개 사본 삭제 완료로 표현하지 않는다. 원문·원시 자료·키·stash 내용은 포함하지 않는다.

## 이전 완료 공개 사본 정리와 합성 검사

main `53ab14e5` 위 전용 브랜치에서 운영 고정 Git·검수 해시·공개 bytes가 일치한 글 17개·자산 15개만 삭제했다. 비공개 Git에 없는 draft 5개·archived 1개와 나머지 자산은 유지했다. 원문·그림에 의존하던 단위/CI 입력을 합성 글·PNG로 전환하고 Git 재추적 방지 회귀를 추가했다. 삭제가 과거 기록의 링크를 깨뜨려 첫 커밋이 차단됐으며, 별도 사용자 승인으로 22개 문서의 링크만 삭제 전 고정 커밋으로 옮겨 본문·결과를 보존했다.

작업별 로컬 커밋은 합성 검사 `108bb34f`, 기존 운영 기록 `adaa627d`, 과거 링크 보존 `3d6455fb`, 검증된 공개 사본 삭제 `20e686d0`로 나눴다. 마지막에는 이번 정제 절차·검증·범위와 공개 검수 해시만 별도 커밋한다. [삭제 대상 대조·실패·회귀·격리 빌드](../../verification/content/2026-11-17-private-git-content.md#2026-11-19-이전-완료-공개-사본-정리)에 조건과 결과를 연결한다.

콘텐츠 51개·lib 373개·저장소 281개·타입·lint를 통과했다. 키 없는 합성 사본 모바일 E2E는 160개 통과·기존 조건 11개 skip이며 기준·timeout·retry를 바꾸지 않았다. 실제 비공개 발행본의 새 빌드와 키 없는 한영 상세 34개·준비 자산 해시 15개도 별도로 확인했다. 원래 18개 작업 트리와 stash 10개는 모두 시작 상태와 동일하다.

기존 다른 기능·초안·원시 자료·공통 지침·stash는 사용자 선택에 따라 보존했다. 개인 경로·원시 대조표·응답·키를 공개 기록에 포함하지 않는다. 이번 요청은 작업별 로컬 커밋까지이며 새 푸시·PR·원격 CI·병합·재배포는 하지 않는다. 후속은 정리 브랜치의 원격 검증과 별도 병합 판단이며 운영 공급 설정·NAS는 유지한다.

## 게시 자동화·현재 인증 경계 검토 · 로컬 기록

2026-11-19 후속 읽기 전용 조회에서 콘텐츠 저장소의 협업자는 소유자 계정 1개, 등록 deploy key 1개는 read-only이며 Actions 기본 토큰은 read·PR 승인 불가였다. 콘텐츠 workflow는 0개다. 현재 에이전트 세션의 인증은 소유자의 관리자 권한이므로 사람과 AI의 쓰기 권한이 분리됐다고 판단하지 않는다. GitHub App 설치 권한 목록은 현재 토큰으로 조회할 수 없어 미확인이다. 비공개 저장소 ruleset·브랜치 보호 조회는 요금제 제한 403을 반환했다.

공개 앱 저장소의 인증 workflow 코드는 main 고정 코드 SHA·별도 Environment·자기 승인 금지·관리자 우회 금지·최종 step의 읽기 키 사용을 요구한다. 실제 `docs-private-content` Environment 조회는 404, 인증 workflow 실행 이력은 0개, 일반 repository secret에 콘텐츠 키 등록도 없었다. 따라서 일반 PR의 합성 검사와 실제 Vercel Production 콘텐츠 빌드는 동작하지만 GitHub의 인증된 실제 콘텐츠 검증은 아직 운영 중이 아니다. 이 미준비 상태를 승인 기준 완화로 해결하지 않는다.

현재 앱 lock의 콘텐츠 SHA 갱신은 수동이며 main 병합 후 Vercel 배포는 자동이다. 추천은 실행·승인 신원 분리 → 보호 Environment와 인증 CI 검증 → 사용자가 공개 승인한 정확한 bytes/콘텐츠 SHA만 검증 → 전용 봇의 lock SHA·URL 집합 갱신 PR 생성 → 기존 CI·승인·병합 → 자동 배포·공개 smoke 검사다. 인증 job은 PR 코드를 checkout하지 않고 검토된 main 코드로 후보 lock을 데이터로 검증해야 한다. 콘텐츠 read-only 키와 공개 앱 PR 작성 자격 증명을 분리하고, 원문·초안·원시 결과는 공개 PR/로그/artifact에 넣지 않는다.

이는 설계 검토이며 workflow 실행·키 발급·Environment 생성·권한/보호 설정·커밋·푸시는 하지 않았다. 기존 검수 hash를 자동 승인하거나 고정 revision을 가변 main/latest로 바꾸지 않는다. 이 추가 기록은 로컬-only이며 공개 검수 해시는 갱신하지 않는다.
