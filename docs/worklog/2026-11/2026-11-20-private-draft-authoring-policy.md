# 비공개 콘텐츠 Git의 초안 작성 규칙 정리

## Summary

KAN-80의 후속으로 새 초안도 비공개 `heap-forge-content`에서 작성하도록 규칙과 가이드를 맞춘다. 비공개 Git 저장 허용과 사람의 공개 검수·게시 승인을 구분한다. 기존 원문·stash·과거 이력·원격 설정은 변경하지 않는다.

## Changed

- 루트·docs `AGENTS.md`와 공개 검수 절차에서 초안의 비공개 Git 저장을 명시하고, 공개 Git 업로드 금지·커밋/푸시 요청 범위·원시 자료의 Git 외부 보관을 유지한다. 기존 CLAUDE 참조 파일은 그대로 둔다.
- [기고 가이드](../../runbooks/docs-contributor-guide.md), [비공개 Git 절차](../../runbooks/docs-private-git-content.md#초안의-기본-작성-위치)에 작성 위치·상태·자산·게시 순서를 통일한다. 기존 렌더링 가이드·branch 보존·NAS 설계 설명은 과거 경로와 현재 지침을 구분한다.
- 비공개 콘텐츠 checkout의 `AGENTS.md`·`CLAUDE.md`·기존 README에 동일한 작성/승인/비밀정보 경계를 로컬 반영한다. 원문·자산·검수 manifest·커밋·원격 권한은 바꾸지 않는다.
- [ADR-0036](../../architecture/adr-0036-private-git-draft-authoring.md)에 신규 작성 위치와 대안을 기록한다. 기존 ADR-0032·0035 결정 본문은 유지한다.

## Notes

초기 로컬 작업의 기준 HEAD는 자동화 작업 커밋 `5c71b847`이었다. 당시 앞선 네 로컬 커밋과 다른 작업 트리·stash를 보존하며 stage·검수 해시 등록·커밋·푸시·키·배포 작업을 하지 않았다. 아래 후속 PR 준비와 구분하며 원격 기본 지침이나 예약 실행 프롬프트가 이미 바뀌었다고 보고하지 않는다.

코드 확인 결과 private-git 준비기는 draft/archived를 제외하므로 비공개 초안 원본을 기존 preview route로 직접 보는 연결은 아직 없다. 이를 구현 완료로 안내하지 않고 공개 코드로 원문 복사·임시 published 전환을 금지한다. 앱 로더·테스트 기준·timeout/retry는 변경하지 않는다.

기존 콘텐츠 준비·공개 업로드 경계 회귀 47개가 통과했다. 새 미리보기나 게시 기능을 추가한 검사는 아니다. 공개 workspace의 신규 파일 포함 12개를 읽기 전용 validator view로 검사해 문서 오류 0개를 확인했다. 대표 공개 검사는 문서 10개의 재승인 요구만 남기며 실제 검수 해시를 임의 갱신하지 않았다. 비공개 checkout은 지침 3개 외 원문·자산·manifest 변경이 없고, CLAUDE 참조 3곳과 저장소별 정책 일관성도 통과했다. 첫 일회성 status 확인의 공백 trim 파서 오류는 NUL 구분 입력으로 고쳐 재검사했다. 제품 코드나 검사 기준을 바꾸지 않았다.

기존 공개 작업 트리 21곳의 사용자 미커밋 bytes·인덱스·status와 시작 stash 목록이 동일하다. 나머지 20개 HEAD와 원본 main의 앞선 외부 pull FF를 그대로 유지했다. 앞선 네 로컬 커밋은 바꾸지 않았다.

재사용할 비공개 저장과 공개 게시의 차이는 기존 [Confluence 주제](https://web-tech-service.atlassian.net/wiki/pages/19922945) v6에 요약하고 기존 본문·실제 근거 링크를 재조회했다. 실행 댓글과 구분하며 새 지식 페이지는 만들지 않았다. KAN-65의 워커 풀 글 추적 항목은 검색됐지만 이번에는 원문 확인·수정·게시를 진행하지 않는다. 공통/앱 AGENTS는 로컬 변경이며 원격 규칙·예약 지침 반영은 미실행이다.

사용자가 양쪽 지침의 검수·커밋·푸시와 공개 PR·원격 CI 확인을 승인했다. 아래 후속 결과를 실제 실행에 따라 기록한다. 기존 초안의 실제 이전·게시, 예약 실행 변경, 개발 preview 연결·키·운영 설정은 계속 제외한다.

## 2026-11-20 후속: 저장소별 커밋·PR 분리

공개 기준은 최신 main `4dedd86e`, 비공개 기준은 `e07988e`다. 다른 세션의 게시 커밋은 기준 상태로만 보존하고 원문·자산·release lock을 변경하지 않는다. 공개 지침 12개와 비공개 지침 3개만 별도 작업 공간에 복사했으며 원래 작업 공간의 미커밋·이전 자동화 4개 커밋은 그대로 둔다. 기존 공개 작업 트리와 비공개 원본 24곳·두 저장소 stash 목록을 새로 보존 대조한다.

최신 main에는 미푸시 자동화의 ADR-0035·lock PR 자동화 절이 없으므로 그 구현을 함께 옮기지 않는다. 신규 ADR-0036은 실제 main의 ADR-0032·0034를 연결하고, 기고 가이드는 존재하는 CI 경계 문서로 연결한다. 원본 지침의 의미는 유지하되 아직 없는 원격 문서나 기능을 적용 완료로 표현하지 않는다.

공개 승인 범위는 이 PR의 지침·정제 작업 기록이며 문서 10개의 최종 인덱스 bytes를 검수 manifest에 등록한다. 비공개 쪽은 사용자 선택대로 AGENTS·CLAUDE·README만 별도 브랜치에 커밋·푸시해 PR을 준비하며 글·자산·검수 목록은 제외한다. 키·권한·활성화 변수·기본 브랜치 병합·workflow dispatch·운영 배포는 실행하지 않는다.

새 작업 공간은 고정 lockfile·ignore-scripts 오프라인 설치로 기존 패키지 1,419개를 재사용했으며 lockfile·설치 훅·대기 중 dotenv skill은 변경/승인하지 않았다. 최신 main 기준 콘텐츠 준비·공개 업로드 경계 44개가 통과했다. 초기 로컬 47개 중 3개는 미푸시 자동화 후보 기능의 회귀로, 이번 PR에 코드와 함께 옮기지 않았다. 최신 main의 기존 테스트·timeout/retry는 바꾸지 않는다. 신규 파일 포함 문서 검사 오류 0개·문서 10개 재승인 요구와 비공개 지침 3개의 대표 패턴 검출 0개를 확인했다. 이는 전체 비밀정보 전수 감사가 아니다.

원래 24곳의 HEAD·미커밋 파일·인덱스·status와 두 저장소 stash 목록의 동일성을 재확인했다. 원문·자산·콘텐츠 lock·워크플로·패키지 파일은 기준 main과 같다. 원격 PR·CI의 최종 결과는 같은 검증 head의 KAN-80 3열 표와 PR 검사 결과에 연결하며, 로컬 검사 성공을 원격 CI·main 병합·운영 성공으로 표시하지 않는다.
