# PR #112 CI 확인과 코드 리뷰

## Summary

[PR #112](https://github.com/IMHOJEONG/web-tech/pull/112)의 head `4ef3fded`와 base `136ef3c4`를 확인하고 변경 파일 43개를 검토했다. 좁은 화면의 Feed 포인터 회귀를 재현했고, 검증 스크립트의 빌드 출처 기록에 보완점을 찾았다. [KAN-83](https://web-tech-service.atlassian.net/browse/KAN-83)에 결과를 연결한다.

## Changed

- 코드 리뷰 결과와 CI 상태를 기록했다. 제품 코드 수정과 리뷰 코멘트의 GitHub 게시 없이 로컬 검토 결과를 전달한다.
- 포인터 재현은 작업 트리 밖의 합성 검증기로 실행했다. 기록의 소스 및 번들 해시가 보관된 빌드와 일치했다.
- 리뷰 보완은 [212369f8](https://github.com/IMHOJEONG/web-tech/commit/212369f8e12aac4f77141b1021326c1c81eb9135)로 PR에 푸시했다. Feed 갱신 중 이전 결과의 공간을 유지하고 링크는 숨김과 `inert`로 비활성화했다. 필터 탐색은 스크롤 위치를 유지한다.
- 검증기는 플래그만 전달해도 기본 경로를 사용하고, 새 빌드에 Git revision과 소스·번들 해시를 기록한다. 기존 빌드는 실제 번들 해시만 출력한다. 최종 검색어·우선순위·페이지의 완료 응답을 기준으로 시간을 계산하고 취소된 보류 요청을 제외한다. [CSP 검증](../../verification/security/2026-11-24-csp-readiness.md#저장소에서-브라우저-이벤트-다시-검증)에 두 커밋과 합성 fixture를 재실행하는 절차를 추가했다.

## Notes

- 최종 검토 시점의 GitHub 체크 23개가 모두 성공했다. GitHub Actions의 반응형 세 폭·본문·오프라인, 타입·린트·단위/계약, 문서, CodeQL, 이미지 빌드와 두 Vercel Preview 상태가 포함된다. GitHub는 충돌 없음과 병합 상태 `BLOCKED`를 함께 표시했다. [GitHub Actions 실행](https://github.com/IMHOJEONG/web-tech/actions/runs/45545798736).
- 좁은 화면에서 조합 중 P2를 직접 클릭하면 검색어는 확정되지만 URL과 결과의 우선순위는 P1에 머물렀다. 기존 회귀는 포커스 이동 후 결과를 기다리고 Space를 누르는 경로를 검사한다. 포인터다운에서 클릭까지 필터 위치를 유지하고 해당 경로를 회귀에 추가할 필요가 있다.
- Feed 검증기는 인자로 받은 번들을 실행하면서 현재 체크아웃 소스의 해시와 고정 날짜·기준 SHA를 결과에 함께 출력한다. 빌드 산출물과 소스의 대응 관계를 입증할 수 있도록 빌드 때 출처를 기록하고 실행 때 대조하는 편이 안전하다.
- CodeRabbit은 코멘트5개를 남겼다. 조합 중 입력 표시와 실제 `compositionend`까지의 요청 관측은 같은 회귀 보완으로 검토했다. 검증기의 플래그 단독 인자 처리 및 연속 검색의 응답 매칭과 앞선 CSP 실험의 재현 명령도 보완 대상이다.
- 로컬 CSP 수집기 테스트 36개가 통과했다. Vercel Preview 체크는 배포 상태이며 공개 CA에서의 수집 경로 기능 시험과 실제 OS IME는 별도 확인 항목이다.
- 기존 Confluence 지식 v45에 기록된 포인터 회귀를 같은 빌드에서 재확인했다. 실행 기록만 갱신하며 새 지식 문서는 필요하지 않다. 공통 지침 변경 없음.
- 리뷰 수정본은 Chromium·Firefox·WebKit의 390px와 1280px에서 6개 Feed 회귀와 링크 순서 150개를 통과했다. Chromium 두 폭에서 조합 후보 표시, 확정 전 요청 0회와 확정 요청 1회, 취소 요청 0회, 조합 중 P2 클릭과 조합 확정 뒤 Space를 확인했다. 이전 PR 빌드는 새 포인터 시험에서 P1 유지로 실패했다.
- 새 head에서 출처가 기록된 빌드와 플래그만 전달한 파일럿이 모두 통과했다. 번들 수정 대조군은 해시 불일치로 중단됐다. CSP 역사적 빌드 21개 조건, CSP 수집기 36개, Feed/Overview 36개와 Vuln Radar 타입·대상 린트가 통과했다.
- 새 head의 [GitHub Actions](https://github.com/IMHOJEONG/web-tech/actions/runs/45550025301)와 Vercel Preview를 포함한 체크 22개가 성공했다. CodeRabbit의 새 리뷰는 호출 제한으로 생략됐다. 기존 인라인 스레드 5개 중 4개는 봇이 해결 처리했고, 조합 확정 전 요청 관측 스레드 1개는 열려 있다. GitHub 병합 상태는 `BLOCKED`다.
- [KAN-83 작업표](https://web-tech-service.atlassian.net/browse/KAN-83?focusedCommentId=10127)와 [Confluence 운영 기록](https://web-tech-service.atlassian.net/wiki/pages/65817?focusedCommentId=21626883)을 갱신하고 다시 읽었다. [Confluence 지식](https://web-tech-service.atlassian.net/wiki/pages/19464193) v46에 조합 중 클릭과 측정 빌드의 판단 기준을 갱신하고 본문·근거 링크·목차 경로를 확인했다. 이 작업 기록과 월간 목차는 로컬에 보관했다. 공통 지침 변경 없음.
- 리뷰 후속 검증에서 동일 head 번들의 Feed 6환경과 링크 순서 150개가 다시 통과했다. 임시 검증기 대조군은 두 번째 조합 후보에서 발생한 확정 전 요청과 일시적으로 변경 후 복원된 URL을 각각 검출했다. 기존 Confluence 지식 v46의 판단 기준을 재검증했으므로 새 지식 문서는 만들지 않았다.
- IME 스레드를 해결 처리하고 리뷰 스레드 5개 모두 해결됨을 재확인했다. GitHub 병합 상태는 `CLEAN`으로 바뀌었다. 공식 CodeRabbit 호출 한도 예외를 확인한 `pnpm pr:squash` 검사 전용 실행이 통과했다. 검토 head는 `212369f8e12aac4f77141b1021326c1c81eb9135`, 최종 메시지 SHA-256은 `c7cb59aa85666fd0832022f294ff4fc013c236f0dd6c19cd69e5b4806bc3ac74`다. Jira 3열 표와 Confluence 운영 기록 v10에서 결과를 재조회했다.
- 사용자 승인 후 같은 head와 메시지로 `pnpm pr:squash --merge`를 실행했다. GitHub에서 `MERGED`와 원격 `main`의 [5dc0e252](https://github.com/IMHOJEONG/web-tech/commit/5dc0e252f2c452b052faf3212eb6b1a0770a9806)를 확인했다. 병합 커밋의 단일 부모는 검토 기준 `136ef3c4`이며 파일 트리는 PR head와 일치한다.
- 같은 SHA에서 [CI](https://github.com/IMHOJEONG/web-tech/actions/runs/45560357144), [Documentation](https://github.com/IMHOJEONG/web-tech/actions/runs/45560357079), [Docs Backend Image](https://github.com/IMHOJEONG/web-tech/actions/runs/45560356934)가 모두 성공했다. 배포 상태도 같은 SHA에서 확인했다. Vercel `web-tech`·`vuln-radar`는 Production, Railway의 Vuln Radar 백엔드는 development다. Jira 3열 표와 Confluence 운영 기록 v11을 재조회했다. 이번 병합 확인은 기존 판단 기준의 적용 사례다.
