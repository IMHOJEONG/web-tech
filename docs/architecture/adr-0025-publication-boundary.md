# ADR-0025: 공개 Git과 게시 상태를 분리한 검수 경계

## 상태와 범위

- 상태: 적용 중
- 대상: 모노레포 공개 Git 업로드, docs 글·에셋·검증 자료
- 결정일: 2026-10-30
- 최종 검토: 2026-10-30
- 적용 위치: KAN-53 로컬 구현. main·원격 CI·훅 설치·NAS 적용은 별도다.

## 배경

`draft`는 사이트 노출을 막을 뿐 공개 Git의 소스를 비공개로 만들지 않는다. 이전 작업의 원시 로그·실험 데이터·초안 보관과 공개 가능한 정제 기록도 구분해야 한다. 최종 diff만 검사하면 중간 커밋에 들어갔다가 삭제된 비밀을 놓칠 수 있다.

## 결정

비공개 초안·원시 실험 자료·자격 증명은 저장소 밖에서 관리한다. 재현 테스트 코드와 합성 fixture는 원시 실험 데이터와 구분한다. 글·공개 에셋·운영 Markdown·정제 증거·데이터 fixture의 변경은 파일 SHA-256에 연결된 명시적 공개 검수 기록을 요구한다. 에이전트는 실제 승인 항목을 임의로 만들지 않는다.

커밋 시 인덱스, 푸시 시 전송할 중간 커밋, CI에서 커밋 범위를 검사한다. 민감 경로·대표 credential 패턴·private 표시·비정상 모드는 승인으로 면제하지 않는다. 오류에는 파일 경로의 해시와 규칙만 출력한다. 자동 검사는 사람의 개인정보·저작권·기술 검수나 인증된 승인 증명을 대체하지 않는다.

기존 전체 이력을 소급 승인하지 않는다. 푸시 검사의 도입 기준은 PR #78 병합 `28fedc40cd72b729bfa69fcf9e2dde736402d53d`다. 새 원격 ref도 이 기준 이후의 실제 전송 커밋을 검사하며 알 수 없는 객체·기준 이전 브랜치는 실패한다. 기존 자료의 전수 감사와 NAS 공개 mount의 승격 검사는 후속 과제다.

공개 저장소의 CI artifact는 비공개 보관소로 간주하지 않는다. 원시 보고서·trace 자동 업로드는 기본 비활성화한다. 합성 fixture만 담긴 증거의 공개가 별도 승인된 경우에만 명시적 변수로 허용한다. 비공개 스토리지 구축이나 원격 설정 활성화는 하지 않는다.

## 대안과 영향

- `draft`와 ignore만 사용: 편하지만 Git 공개·강제 add·중간 커밋 유출을 막지 못한다.
- 모든 테스트를 비공개: 재현성과 회귀 차단을 잃는다. 원시 관측 자료만 비공개 기본값으로 둔다.
- 패턴 탐지만 사용: 개인정보·이미지·미지의 비밀 형식을 놓친다. 해시 검수와 직접 확인을 결합한다.
- 서명된 승인 서비스: 더 강한 신원 증명이 가능하나 현재 관리자/AI 권한 분리가 미완료다. 로컬 JSON을 사람 승인 증명으로 과장하지 않는다. KAN-33의 별도 권한 분리와 연결한다.
