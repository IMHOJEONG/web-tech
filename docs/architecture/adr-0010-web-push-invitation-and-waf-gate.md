# ADR-0010: 웹 푸시는 초대 세션과 IP 제한을 확인한 뒤 활성화한다

## 상태와 범위

- 상태: 적용 중
- 대상: docs 브라우저용 웹 푸시 BFF와 운영 활성화 절차
- 결정일: 2026-10-03
- 최종 검토: 2026-10-03
- 코드의 접근 제한과 기본 비활성화는 적용했다. 실제 Production WAF와 NAS 활성화는 미검증이다.

## 배경

[ADR-0009](adr-0009-docs-web-push-experiment.md)의 서버 간 API 토큰은 NAS를 보호하지만, docs의 공개 BFF를 사용하는 방문자를 식별하지 않는다. Origin 검사는 사용자 인증이 아니므로 공격자는 요청을 만들어 실험 구독 20개나 프로세스 전체 요청 한도를 소진할 수 있다. 소규모 실험에 계정 시스템을 도입하지 않고 참여 범위를 좁힐 필요가 있다.

## 결정

- `BLOG_PUSH_ENABLED`와 Nest의 `PUSH_ENABLED`는 기본 `false`를 유지한다. 코드를 저장소에 게시하는 것과 운영 활성화는 별개다.
- 참여자는 별도로 전달받은 무작위 초대 코드를 입력한다. docs는 코드를 검증하고 1시간짜리 HMAC 서명 세션을 HttpOnly 쿠키로 발급한다. 운영에서는 Secure, SameSite=Strict, Path=/api/push를 사용한다.
- 초대 코드와 세션 서명 키를 분리한다. 참여자가 코드를 알아도 세션을 임의 발급할 수 없게 하며, API 토큰을 두 값으로 재사용하지 않는다. 쿠키 서명에는 초대 코드의 해시를 포함해 코드 또는 서명 키 교체 시 기존 세션을 거부한다.
- config 조회와 구독 등록·해지는 세션 확인 후에만 NAS로 전달한다. 코드 확인은 알림 허용이 아니며, 브라우저 권한은 이후 구독 버튼 클릭으로만 요청한다.
- 운영에서는 `/api/push` 및 하위 경로 전체에 IP별 10회/60초 Fixed Window, 초과 429 WAF 규칙을 먼저 게시·검증한다. 초대 확인 경로도 포함한다.
- `BLOG_PUSH_WAF_VERIFIED=true`가 없으면 Production BFF는 503으로 닫힌다. 이는 운영자의 검증 확인 값이지 WAF 상태를 자동 확인하는 기술이 아니다. 실제 규칙이 제거되면 이 값도 내리고 비활성화한다.
- 비밀값은 URL, localStorage, 응답, 로그, Git에 넣지 않는다. 초대 코드는 확인 요청의 JSON body에만 전달한다.

## 대안과 영향

- IP 제한만으로는 여러 IP를 사용하는 공격자와 구독 입력 위조를 막지 못한다. 초대 제한을 함께 둔다.
- 공유 코드는 소수의 신뢰한 참여자에게만 적합하다. 개인 식별·개별 회수·사용자별 구독 수 제한이 없고 코드 유출이나 참여자 악용을 완전히 막지 못한다. 공개 서비스 전에는 일회성 개인 초대 또는 계정 인증과 분산 quota를 별도로 결정한다.
- NAS의 20개/30회 제한은 실험 운영 기준이지 웹 푸시 표준 한도가 아니다. 인증된 참여자도 이 한도를 소진할 수 있다. WAF는 그 위험을 줄이는 추가 계층이다.
- 초대 세션 만료·코드 회전은 기존 구독 삭제나 알림 권한 철회가 아니다. 이미 동의한 구독자는 계속 테스트 알림을 받을 수 있다. 해지 API를 사용하려면 만료 후 초대 코드를 다시 확인한다.
- 세션 탈취는 TTL 내 접근을 허용할 수 있다. HttpOnly/Secure가 XSS나 기기 침해를 모두 해결하지 않는다. 서명 키 교체로 세션을 일괄 폐기한다.
- WAF는 NAT를 공유하는 참여자도 함께 제한하며 지역별로 계산한다. Hobby의 rate limit 규칙 한도가 이미 사용 중이면 기존 revalidation 보호를 삭제하지 않고 활성화를 보류한다.
- 자동 게시 대신 대상 프로젝트·기존 draft·요금제 한도를 확인한 뒤 수동 게시한다. 운영 설정과 실제 비밀값은 이번 변경에 포함하지 않는다.
