# ADR-0003: 피드와 문서 인덱스의 역할 분리

## 상태와 범위

- 상태: 적용 중
- 대상: docs 앱의 `/feed`, `/docs` 및 검색 진입
- 결정일: 2026-05-05
- 최종 검토: 2026-09-21
- 대체: [ADR-0001](adr-0001-docs-feed-main.md)

## 배경

두 경로가 같은 `MainFeed` 화면을 보여주면 사용자는 큐레이션과 전체 문서 검색의 차이를 알기 어렵다. 헤더 검색 결과를 표시할 별도 맥락도 필요했다. 원문 데이터는 공유할 수 있지만 화면의 목적은 다르다.

## 결정

`/feed`는 읽을 글을 발견하는 큐레이션 화면, `/docs`는 전체 문서의 검색·필터·인덱스 화면으로 유지한다. 검색 결과는 `/docs?q=...`에 둔다. 페이지 컴포넌트는 각각 `MainFeed`와 `DocsIndex`를 렌더링하며, 같은 문서를 참조해도 표현을 공유하도록 강제하지 않는다.

## 대안과 영향

- 하나의 화면을 두 경로에서 재사용하면 구현은 단순하지만 URL의 역할과 검색 맥락이 흐려진다.
- 경로별 화면은 탐색 목적을 분명하게 하지만, 공통 데이터 변환이나 카드 표현을 재사용할 때 경계를 판단해야 한다.
- 검색 결과를 `/feed`에 합치면 큐레이션과 질의 결과가 섞이므로 채택하지 않았다.
- 두 경로가 실제로 동일한 사용자 과제를 수행하게 된다면 역할 분리를 재검토한다. 현재의 정렬·필터·검색 흐름은 별도로 유지한다.
