# ADR-0032: 비공개 Git 발행본을 빌드 입력으로 사용

## 상태와 범위

- 상태: 적용 중
- 대상: docs의 선택형 `private-git` 콘텐츠 공급 경로
- 결정일: 2026-11-17
- 최종 검토: 2026-11-19
- 적용 위치: KAN-80 운영 전환 전용 브랜치와 이전 보호 Preview. 선택형 코드는 기본 `legacy`를 유지하며 공개 검수·CI·별도 PR 병합 뒤 Production을 전환한다. 현재 전환 실행 전이며 공개 원문 삭제는 범위 밖이다.

## 배경

공개 서비스 코드와 원문 저장 위치를 분리한다. 글을 제공하기 위해 NAS API의 가용성·자격 증명·게시 캐시를 계속 관리해야 하는 부담을 줄인다. 이전 KAN-80 Preview 구현은 별도 커밋에 있었으며, 현재 main의 기본 로더는 여전히 로컬·NAS 병합이다.

비공개 저장소에 있다는 사실은 웹사이트 비공개를 뜻하지 않는다. 빌드에 포함된 글과 자산은 독자에게 공개된다. Git 이력에 공개된 원문은 현재 트리에서 삭제해도 과거 이력에서 사라지지 않는다.

## 결정

코드는 공개 저장소, 원문은 비공개 콘텐츠 저장소에서 관리한다. 페이지 요청 중 GitHub나 NAS를 호출하지 않고, 빌드가 고정 Git SHA의 승인된 발행본을 준비한다. 운영 전환은 원문 누락·검수·빌드·배포 검증이 끝난 뒤 진행한다.

1. `content-release.lock.json`에 저장소·40자리 SHA·정확한 공개 URL 집합을 고정한다. 브랜치명과 `latest`는 허용하지 않는다.
2. 빌드의 Git 인증에는 콘텐츠 저장소 한 곳의 읽기 전용 deploy key를 사용한다. 키와 bare Git 객체는 임시 디렉터리에만 두고 종료 시 정리한다. Next 설정에는 모드와 공개 가능한 리비전만 포함한다.
3. `published`와 파일 SHA-256 공개 검수를 모두 요구한다. 자격 증명 패턴·비공개 표시·비정상 Git 모드·크기 상한은 승인으로 면제하지 않는다. 검수 목록은 비공개 저장소의 고정 커밋에 둔다. 기존 공개 검수 기록은 동일 bytes의 이전에만 사용할 수 있다.
4. 원문 문법·메타데이터·본문 작성 규칙·URL 중복·참조 자산을 검증한다. 초안·archived 글·원시 자료·미참조 자산·Git 객체는 배포 입력에 복사하지 않는다. 외부 HTTPS 미디어는 별도 공개 자산 의존성이므로 NAS 독립을 자동 보장하지 않는다.
5. `private-git` 모드는 목록·본문·검색에서 NAS 설정을 무시한다. 없는 글은 NAS fallback이 아니라 없는 글로 처리한다. 준비·검수 실패는 빌드를 실패시키며 기존 배포를 자동 수정하지 않는다.
6. Next trace에는 해당 리비전의 준비된 원문만 포함하고 기존 원문 디렉터리는 제외한다. 로컬 검색 digest에도 리비전을 포함한다. 빌드 입력·검수가 매번 실행되도록 docs의 Turbo build 캐시는 사용하지 않는다.

승인 JSON은 콘텐츠 검수를 추적하는 장치이지 사람의 암호학적 서명은 아니다. 같은 계정이 원문·검수 목록·배포를 모두 수정할 수 있는 권한 문제는 기존 별도 신원 분리 과제로 남긴다.

2026-11-19 사용자는 기존 승인된 글 17개·자산 15개에 한정해 별도 PR 검수·병합 후 운영 전환을 승인했다. NAS 전용 글은 사용자가 수동 이전하며 이번 발행 집합에 추가하지 않는다. 일반 PR은 PR #97의 합성 문서만 사용한다. 실제 콘텐츠는 승인된 main SHA를 고정한 Vercel 빌드에서 읽고 후보 배포를 검증한 뒤 도메인에 반영한다. GitHub 인증 CI의 보호 Environment·실행자/승인자 분리는 후속 과제로 유지하며 미실행을 인증 CI 성공으로 표시하지 않는다. Vercel의 Production 전용 키는 일반 PR·다른 Preview branch·GitHub 일반 secret에 등록하지 않는다. 플랫폼의 Production 런타임에서도 환경 변수에 접근할 수 있는 점은 별도 위험으로 남으며 완전한 키 격리를 주장하지 않는다.

## 대안과 영향

- NAS 유지: 즉시 API 반영에는 유리하지만 운영 경계와 장애 fallback을 계속 관리해야 한다. 전환 완료 전까지 기존 경로는 복구용으로 보존한다.
- 요청마다 비공개 Git 조회: 토큰과 Git 가용성이 사용자 요청에 연결된다. 이번에는 채택하지 않는다.
- 빌드 시 전체 저장소 복사: 간단하지만 초안·원시 자료·자산이 결과물에 섞일 수 있어 채택하지 않는다.
- 승인된 발행본 빌드: 콘텐츠 변경에 새 빌드가 필요하고 private Git 인증 실패 시 새 배포가 막힌다. 대신 운영 요청은 원문 서버에서 분리된다.

이 ADR은 `private-git` 모드에만 적용한다. NAS snapshot 계약과 기존 fail-fast 정책을 삭제하거나, 운영 설정이 이미 전환됐다고 표시하지 않는다.
