# 콘텐츠 캐시 개선 우선순위

## 상태와 범위

- 상태: 적용 중
- 대상: docs 콘텐츠 캐시 검증 및 후속 운영 개선
- 최종 검토: 2026-09-22

## 배경

300초 TTL과 인증된 `POST /api/revalidate/content`는 이미 적용되어 있다.
이 문서는 기존 정책을 대체하지 않고 검증과 운영 보완 순서를 정의한다.
TTL은 주기적인 작업이 아니며, 300초 이내 반영을 보장하지 않는다.
만료 후 요청과 성공적인 원본 조회가 있어야 갱신된다.

## 대안과 영향

캐시 모델을 한 번에 교체하는 대신 기존 TTL·웹훅을 유지하면서 단계별 효과를 검증한다. 표의 예정·검토 항목은 적용 완료를 뜻하지 않는다.

### 검증 원칙

- 서버 호출 로그만으로 캐시 적중 여부를 추정하지 않는다. 실제 원본 HTTP 호출 수를 측정한다.
- 같은 페이지가 캐시되었다는 사실만으로 Data Cache 적용을 증명하지 않는다.
- 테스트 전용 동적 Route Handler에서 실제 콘텐츠 함수를 호출해 Data Cache를 검증한다.
- 잘못된 인증이 기존 캐시를 만료시키지 않는지도 확인한다.
- 로컬 next start 결과와 Vercel의 CDN·다중 인스턴스 동작 검증은 구분한다.
- Router Cache, 브라우저 이미지 캐시, 자동 파일 감시, TTL 만료 후 장애 동작은 이번 테스트 범위 밖이다.
- 요청 제한은 서버리스 인스턴스별 메모리 카운터만으로 구현하지 않는다.
