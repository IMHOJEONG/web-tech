# ADR-0031: 검색 Drawer와 경량 자동완성을 분리한다

## 상태와 범위

- 상태: 적용 중
- 대상: docs 헤더 검색·자동완성 API
- 결정일: 2026-11-14
- 최종 검토: 2026-11-14
- 로컬 작업 트리 구현이다. 커밋·푸시·main 병합·운영 배포는 하지 않았다. 입력 계약의 ADR-0007을 대체하지 않는다.

## 배경

사용자가 데스크톱·모바일에서 같은 Drawer 검색과 자동완성·문서 목록을 요청했다. 기존 헤더는 작은 입력 팝오버만 제공하고 결과는 제출 후 볼 수 있었다. 공용 UI에는 Base UI Dialog 기반 Sheet가 이미 있다.

기존 `/api/search`는 본문과 HTML preview까지 반환한다. 입력할 때마다 이 응답 전체를 내려받을 이유는 없다. 화면별로 검색 관련도를 다시 구현하면 전체 결과와 자동완성이 달라질 수 있다.

## 결정

- 검색 버튼은 두 화면 모두 오른쪽 Sheet를 연다. 모바일에서는 전체 폭, 큰 화면에서는 최대 36rem이며 내부 결과만 스크롤한다. 공용 컴포넌트·전역 토큰은 바꾸지 않는다.
- `Search`는 URL·locale 변경 시 상태를 초기화하고, `SearchDrawer`는 열림·입력 상태, 본문은 폼·키보드, 결과 목록은 로딩·오류·문서 표현을 담당한다. 요청 수명은 별도 훅에서 관리한다.
- `/api/search/suggestions?q=...`는 기존 `getSearchData`의 검색·원격 우선·로컬 fallback·관련도 순서를 재사용한다. 결과는 최대 8개 문서의 제목·요약·이동 경로·분류·읽기 시간만 반환한다. `content`, HTML preview, 출처 배지는 제외한다.
- `count`는 전체 일치 수이며 경량 목록 길이와 다를 수 있다. 추천 검색어 최대 5개는 기존 추천어와 상위 결과 태그에서 추출한다. 빈 입력은 날짜순 문서·추천어를 제공하며 인기 통계라고 부르지 않는다.
- 입력은 ADR-0007의 첫 q·NFC·공백·40 code point·IME 계약을 유지한다. Drawer 안에서만 250ms debounce 후 조회하고, 이전 요청을 취소하며 현재 요청의 결과만 반영한다. IME 조합 중에는 조회·제출·Escape 닫기를 미룬다.
- 클라이언트 조회는 8초에 취소하고 재시도 안내를 보여준다. 닫을 때도 요청을 정리한다. 이는 서버 작업을 강제로 중단하거나 NAS 실패 정책을 바꾸는 장치가 아니다.
- combobox·listbox·active descendant로 방향키 선택·Enter 상세 이동을 제공한다. 명시 제출은 기존 `/docs?q=...`로 이동한다. 전체 결과의 URL·history·중복 제출 방지·native GET 형태는 유지한다.
- 입력창에서는 active descendant로 선택하고, 목록 링크에 포커스가 옮겨가면 링크의 방향키 처리로 실제 포커스를 이동한다. 목록의 첫/끝은 순환하고 Enter는 링크의 기본 이동을 유지한다. 실제 포커스와 선택 강조를 동기화하며 IME 조합 중 방향키는 가로채지 않는다.
- Sheet의 포커스 격리·Escape·트리거 복귀를 재사용한다. 수화 전 버튼은 비활성화한다. 결과 Link의 prefetch를 끄고 입력 중 상세 페이지의 자동 요청을 만들지 않는다.
- 검색어를 로컬 저장소나 별도 분석 로그에 기록하지 않는다. 다만 GET URL의 q는 기존 인프라 접근 로그에 남을 수 있으므로 비밀 입력 창으로 보지 않는다. API는 공개 문서 검색이며 인증이나 WAF 설정을 새로 변경하지 않는다.

## 대안과 영향

- 작은 팝오버를 유지하면 변경은 적지만 모바일 결과 탐색 공간과 기기 간 일관성이 부족하다.
- 전체 검색 API를 매번 사용하면 endpoint는 재사용되지만 본문·preview 전송이 커진다. 별도 경량 projection으로 검색 엔진과 표시용 응답을 분리했다.
- 입력마다 URL을 변경하면 전체 목록·필터·history가 흔들린다. Drawer 미리보기와 명시적 전체 결과 이동을 나눴다.
- 범용 Command 라이브러리를 추가하지 않고 기존 Sheet와 접근성 패턴을 조합했다. 새 의존성·공용 UI API 변경은 없다. 오타 교정·퍼지 검색·실기기 키보드 대응은 추가 과제다.
- 기존 `max-w-xl`은 이 저장소에서 간격 토큰 80px로 해석돼 Drawer를 좁혔다. 검색 패널에만 `sm:max-w-[36rem]`을 사용하며 전역 토큰 재설계는 별도 과제로 남긴다.
