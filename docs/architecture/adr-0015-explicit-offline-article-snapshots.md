# ADR-0015: 직접 저장한 공개 글만 오프라인 스냅샷으로 제공

## 상태와 범위

- 상태: 적용 중
- 대상: docs 공개 상세, 브라우저 CacheStorage, 기존 푸시 Service Worker
- 결정일: 2026-10-17
- 최종 검토: 2026-10-18
- 로컬 구현과 Chromium 검사 범위다. 운영 배포·실제 Safari/Firefox·기기는 미검증이다.

## 배경

원격 서버 장애 시 로컬 대체만으로는 사용자 인터넷 전체가 끊긴 상황을 해결하지 못한다. 사용자는 자동 수집 대신 글에서 ‘오프라인 저장’을 직접 누른 경우에만 저장하기로 선택했다. Next.js HTML·RSC·클라이언트 청크 전체를 보관하면 배포 버전 불일치와 비공개 데이터 혼입 경계가 복잡해진다.

## 결정

공개 상태가 `published`인 일반 상세에 저장 UI를 둔다. preview·draft 화면에는 두지 않는다. 저장 버튼이 렌더링된 본문만 읽기 전용 HTML로 정규화하여 보관한다. API 응답, 인증 헤더, 쿠키, 검색어와 페이지 전체 DOM은 스냅샷에 넣지 않는다.

- UI·DOM 정규화·메시지 전송은 `feature/offline`로 분리한다. Next.js 응답 대신 작은 정적 `/offline.html`·reader JS·CSS를 저장한다. 저장본은 Next 런타임 없이 읽는다.
- 기존 `/push-sw.js` URL·scope를 유지하고 오프라인 코드를 import한다. 별도 Worker 등록으로 푸시 구독을 덮어쓰거나 알림 권한을 요구하지 않는다. CSP의 네트워크 허용은 같은 출처로 제한한다.
- 키는 동일 출처 `/ko/docs/...`, `/en/docs/...`의 query·fragment 없는 경로만 허용한다. 메시지 발신 Client의 출처·현재 상세 경로와 저장 대상이 일치해야 한다. 목록·삭제는 저장소 화면에서도 가능하다.
- 일반 앱은 `published`일 때만 저장 버튼을 제공한다. Worker가 서버의 게시 상태를 다시 인증하는 구조는 아니다. 이미 같은 출처에서 실행되는 악성 스크립트나 DevTools 조작에 대한 새 인증 경계를 주장하지 않는다.
- 본문 태그·속성 allowlist와 텍스트 escaping을 적용한다. script·iframe·form·이벤트 속성·style·SVG를 보관하지 않는다. 저장본 CSP는 script·form·외부 자원 실행을 차단한다. 내부 `#anchor`는 유지한다.
- 이미지 최대 5개를 병렬 시도한다. 같은 출처의 Next 이미지 최적화·`/diagrams/`·`/image/` 래스터만 대상이며 이미지당 256KiB·2.5초로 제한한다. 인증정보 없이 요청하고 성공한 바이트만 data URL로 넣는다. 외부 이미지·SVG·큰 파일·실패한 이미지는 안내 문구로 대체하며 본문 저장 성공과 구분해 알린다.
- 글은 최대 10개, 최종 스냅샷은 글당 2MiB다. 변환 전 본문도 1MiB로 제한한다. 한도 초과 시 자동 삭제하지 않고 사용자에게 정리를 안내한다. 쓰기는 Worker에서 직렬 처리한다.
- 저장 성공 응답과 목록 확인 후 성공을 안내한다. 수정된 글도 사용자가 업데이트를 눌러야 교체한다. 저장 시각과 오래된 복사본이라는 안내를 표시한다. 개별 삭제·확인 후 전체 삭제를 지원한다.
- 본문 Suspense의 로딩 표시가 남아 있으면 저장을 거부한다. `Loading...`을 글로 보관하지 않는다. 기존 본문에 H1이 있으면 보존하고 reader의 제목 H1만 추가하지 않는다. 원문의 제목 계층을 임의로 변경하지 않는다.
- 실제 navigation의 네트워크 연결 실패 때만 저장본 또는 저장한 글 목록으로 대체한다. 정상 404를 저장본으로 숨기지 않는다. API·RSC·POST·인증 응답은 캐시하지 않는다. Next 클라이언트 라우팅 실패를 전부 복구하는 기능은 아니다.

## 대안과 영향

- 전체 사이트 precache/PWA: 최초 다운로드·배포 청크 갱신·인증 예외 비용이 커서 제외한다. 설치형 앱도 이번 범위가 아니다.
- 열어본 글 자동 저장: 사용자가 선택하지 않은 글을 보관하므로 제외한다.
- Service Worker 없이 IndexedDB만 사용: 데이터 보관은 가능하지만 인터넷이 끊긴 뒤 읽기 화면 자체를 열기 어렵다.
- Serwist 등 범용 캐시 도구: 복잡한 자원 전략에는 유용하나 현재의 작은 opt-in 스냅샷 계약에는 의존성을 추가하지 않았다. 범위가 확대되면 재검토한다.

첫 방문부터 오프라인인 경우, 저장하지 않은 글, 전체 검색, 인터랙티브 예제·복사 버튼의 오프라인 동작은 지원하지 않는다. 코드 텍스트·표·기본 접기·앵커는 읽을 수 있다. 작은 정적 reader는 기존 디자인의 중립색·주황 강조를 따르되 온라인 화면과 완전히 같지는 않다. 임의 query가 포함된 참고 링크는 검색어 보관을 피하기 위해 query를 제거하므로 원문 링크와 동작이 달라질 수 있다.

HTTPS 또는 localhost가 필요하다. 저장본은 해당 브라우저·프로필·출처에만 남으며 동기화·백업하지 않는다. 브라우저의 공간 회수·데이터 삭제로 사라질 수 있고 사용자가 이후 비공개로 바꾼 글의 기존 복사본을 강제 회수할 수 없다. 공개 글의 다운로드 성격을 전제로 한다. Worker 갱신 때 같은 형식의 글 캐시는 유지하고 이전 reader shell만 정리한다.
