# ADR-0017: Overview의 API 장애를 패널 단위로 격리

## 상태와 범위

- 상태: 적용 중
- 대상: vuln-radar Overview 로컬 작업 트리. 원격 CI·운영 배포 미검증.
- 결정일: 2026-10-22
- 최종 검토: 2026-10-22
- 추적: [KAN-27](https://web-tech-service.atlassian.net/browse/KAN-27)

## 배경

Overview는 여섯 API를 독립 조회하지만, health·수집 상태·watchlist 중 하나라도 실패하면 정상 통계·Feed·KEV까지 전체 오류 화면으로 가렸다. 갱신 중 실패도 기존 캐시를 숨겼고 느린 보조 요청이 전체 초기 화면을 지연시켰다.

## 결정

API별 Query 캐시를 유지하고 공통 패널 경계가 `pending / ready / stale / unavailable`을 판별한다. 이것은 React 렌더 예외용 ErrorBoundary가 아니라 비동기 데이터 상태의 경계다.

- 값이 있으면 실패한 refetch에서도 본문을 유지한다. 갱신 실패·오래된 값일 수 있음을 표시하고 **이 브라우저가 마지막으로 응답을 받은 시각**을 표시한다. 수집 성공·DB 반영 시각으로 부르지 않는다.
- 값이 없으면 해당 패널의 로딩 또는 실패 안내를 표시한다. 빈 배열·실제0과 요청 실패를 구분하며, 실패를 빈 데이터·0으로 변환하지 않는다.
- 최초 실패 후 재시도 중에도 실패 안내와 비활성화된 버튼을 유지한다. 오류 자체가 fetch 시작 때 초기화되어도 마지막 오류 시각으로 이 상태를 유지한다. 성공하면 안내를 제거한다.
- 패널 재시도는 소유 API만 refetch한다. 전체 새로고침은 기존 여섯 API를 요청한다. 기존 Query 설정의 자동 재시도1회·staleTime30초·화면 polling60초·클라이언트 요청 timeout8초는 변경하지 않는다. 자동 재시도 소진 후 경고/버튼이 나오며 다음 polling·수동 재시도로 복구할 수 있다. 창 포커스 복귀에 의한 refetch는 기존대로 꺼져 있다. 총 소요 시간을8초로 보장하는 정책은 아니다.
- 모든 API가 캐시 없이 실패를 확정했을 때만 전체 오류 화면을 사용한다. 하나라도 응답 또는 대기 상태가 있으면 독립 패널을 유지한다. 건강한 health 응답은 다른 API의 성공을 증명하지 않는다.
- 핵심·전체 통계는 overview 응답, 최근 목록은 Feed, watchlist 숫자는 watchlist, 수집 관측은 status, KEV 행은 KEV 응답을 사용한다. 핵심 패널의 중복 Feed 링크와 통계 옆 가짜 장식 그래프를 제거하고 최근 링크는 독립 Feed에 유지한다. status 실패로 통계가 실패하지 않으며 누락된 집계 필드는 `—`다. 별도 시점 status 숫자로 덮지 않는다.
- KEV 설명의 health/status는 선택 정보이며 실패한 요청의 오래된 부가 메타데이터는 미확인으로 표시한다. 행은 유지하고 KEV 시각은 KEV 응답의 `generatedAt`을 사용한다. health는 독립 연결 안내/재시도로 제공한다.

기존 전체 페이지 skeleton 대신 공통 패널 로딩을 사용한다. 한영 문구와 접근 가능한 상태 안내·명시적 재시도 이름·키보드 focus 스타일을 공유한다. backend 계약·DB·서버 인증·배포 환경변수는 변경하지 않는다.

## 대안과 영향

전체 오류 화면은 구현이 단순하지만 보조 API 장애를 전체 장애로 확대한다. 임의 빈 값으로 계속 표시하면 실패를 정상0으로 오해하므로 선택하지 않는다. 별도 거대 집계 API는 원자적 snapshot에 유리하지만 현재 독립 갱신·부분 복구 목표와 다르고 backend 변경을 요구한다.

각 패널의 마지막 수신 시각은 다를 수 있다. 같은 순간의 일관된 DB snapshot을 보장하지 않는다. 캐시는 현재 브라우저 세션의 Query 캐시이며 새로고침 후 오프라인 열람을 보장하는 영속 저장이 아니다. 장애 동안 요청을 영구 중단하는 circuit breaker나 서버 health 기반 차단도 아니다. 복수 패널의 중복 overview 경고는 같은 요청을 가리키며 별도 요청을 만들지 않는다.

운영에서 요청 폭주·장기 장애·일관된 snapshot이 문제이면 retry/backoff·서버 집계·보관 기간을 별도 재검토한다. 이번 작업에 새로운 라이브러리나 무제한 자동 재시도는 도입하지 않는다.
