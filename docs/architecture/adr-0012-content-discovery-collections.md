# ADR-0012: 실제 공개 글로 태그와 읽기 모음을 구성한다

## 상태와 범위

- 상태: 적용 중
- 대상: docs의 `/docs` 인덱스·검색
- 결정일: 2026-10-04
- 최종 검토: 2026-10-04
- 적용 위치: feature/docs 작업 트리. 운영 배포 검증은 별도다.

## 배경

태그는 frontmatter와 원격 계약에 이미 있지만 인덱스에서 표시만 한다. 독자가 관련 글을 이어 읽을 실제 순서가 필요하며 초안이나 없는 글로 빈 탐색 UI를 만들지 않는다.

## 결정

1. `tag`와 `collection`을 URL query로 관리한다. 태그·모음·섹션은 교집합이며 기존 검색·정렬·페이지네이션 링크가 선택을 유지한다. 필터 변경은 1페이지로 돌아간다. 새 검색 제출은 ADR-0007대로 새로운 검색을 시작한다.
2. 태그는 현재 공개 목록에서 집계한다. NFKC·trim·소문자로 비교하고 글 하나의 중복 태그는 한 번만 센다. 상위 8개와 현재 선택을 보여주고 나머지는 접어둔다.
3. 초기 시리즈는 브라우저 런타임, React/Next.js 경계 노트를 묶는다. 학습 경로는 포커스 체크리스트→Drawer 경고 조사 순서다. 후자는 확정된 해결 가이드가 아니라는 설명을 유지한다. 시리즈는 편집자가 묶은 글이며 authored 연재 회차를 선언한 것은 아니다.
4. 모음 레지스트리는 `widgets/docs-index/model/content-collections.ts`에서 ID·종류·한/영 설명·canonical href 순서를 관리한다. 현재 조회 목록과 교차해 두 글 이상 있을 때만 선택지로 보여준다. draft·archived와 원격 장애로 없는 글의 링크를 만들지 않는다. 같은 href의 원격 우선·로컬 fallback은 기존 조회 규칙을 따른다.
5. 추천 읽기 순서는 별도 ordered list로 표시하며 아래 문서 목록은 정렬·필터를 따른다. 알려지지 않은 태그/모음은 전체 결과로 조용히 넓히지 않고 빈 결과와 해제를 제공한다.
6. 추가 API 요청·원격 계약 필드·백엔드 변경 없이 기존 조회 결과를 재사용한다. 모델, 태그 UI, 모음 UI를 분리한다. 허브의 topic 필터와는 별개다.

## 대안과 영향

태그 유사도만으로 순서를 추정하면 선행 지식과 조사/해결 글의 차이를 보장하지 못한다. frontmatter `series`·회차·학습 목표와 원격 API를 바로 확장하면 서버에서 편집할 수 있지만 NAS 이미지와 계약의 동시 변경이 필요하다. 현재는 작은 명시적 레지스트리를 선택하며 모음 수정에는 프론트 재배포가 필요하다. CMS 편집·진도 저장·전용 상세 경로는 이번 범위가 아니다.

글 추가 시 공개 상태·실제 canonical 주소·설명·순서를 검토하고 `test:lib`를 실행한다. 기존 참조가 초안/삭제 글로 바뀌면 참조 테스트가 실패한다. 원격 전용 글을 등록할 때에는 공개 fixture도 마련해야 한다. 편집 빈도와 모음 규모가 커지면 공유 스키마와 CMS 저장을 재검토한다.
