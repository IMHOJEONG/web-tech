# 블로그 전면 UI 개선 제안

## 상태와 범위

- 상태: 적용 중
- 대상: docs의 탐색·목록·글 상세·소개 화면
- 최종 검토: 2026-10-31
- 추적: [KAN-56](https://web-tech-service.atlassian.net/browse/KAN-56)

운영 화면 조사 후 사용자가 선택한 글 중심 저널을 실제 앱에 로컬 적용했다. Feed·Docs·주제 허브·상세·About과 관련 스켈레톤의 조판·공통 표시를 바꿨다. 기존 콘텐츠·URL·공용 패키지 API·배포는 변경하지 않았다. 커밋·공개 Git 업로드 승인을 뜻하지 않으며 기존 ADR을 대체하지 않는다.

### 현재 적용 범위

- 로컬 적용: 반복 기본 썸네일 생략, 행형 목록, 공통 페이지 제목/간격, 모든 글 메뉴 진입, Backend 탐색 링크, 검색 문맥 정리, 모바일 접이식 목차, 상세 읽기 폭과 제목 조정.
- 기존 모바일 하단 바는 제거하지 않고 텍스트 라벨을 추가했다. 상위 메뉴의 3개 항목 전면 교체·빈 Mobile 메뉴 숨김은 이번 범위에 넣지 않았다.
- 후속 요청으로 Root Landing도 짧은 소개 → 최근 글 → 주제 탐색 순서로 적용했다. Feed·Docs의 독립된 역할과 최신 글만 분리하는 Suspense 경계는 유지한다.
- 기존 Base UI와 데이터 흐름은 유지한다. [구현 검증](../verification/accessibility/2026-10-31-blog-journal-implementation.md)은 로컬 결과이며 운영 배포와 실제 독자 만족도 검증은 남아 있다.

## 배경

현재 사이트는 카드 전체 링크, 검색, 주제 필터, 페이지네이션과 데스크톱 목차를 이미 제공한다. 전면 개선을 모든 기능의 재작성으로 해석하지 않는다. 우선 문제는 반복 기본 썸네일, 서로 다른 페이지 위계, 모바일의 긴 글 이동, 검색 요약의 원문 기호다. 당시 화면과 측정 조건은 [운영 화면 보고서](../verification/accessibility/2026-10-31-blog-ui-review.md)에 둔다.

독자 유형은 다음 작업 가설로 구분한다. 인터뷰로 확인한 페르소나는 아니다.

| 읽으러 온 이유                | 독자가 먼저 알아야 할 것                      | 우선 화면        |
| ----------------------------- | --------------------------------------------- | ---------------- |
| 처음 방문해 읽을 글 고르기    | 어떤 문제를 다루고, 읽으면 무엇을 알게 되는가 | Feed             |
| 특정 개념·이전 글 다시 찾기   | 제목·주제·검색 문맥이 내 질문과 맞는가        | Docs와 주제 목록 |
| 외부 링크로 긴 글에 바로 도착 | 글의 범위·전제·현재 위치·다음 절              | 상세             |

## 결정

### 제안 방향: 글은 저널처럼, 탐색은 색인처럼

주황색 HEAP-FORGE 브랜드와 현재 한국어 서체를 유지한다. 본문은 단정한 산세리프, 날짜·언어·짧은 보조 정보는 제한된 모노스페이스로 구분한다. 전체 사이트를 터미널처럼 만들거나 모든 문장을 대문자·모노스페이스로 바꾸지 않는다.

- Feed는 읽을 이유를 보여준다. 추천 글 하나에만 큰 위계를 주고 나머지는 편안한 행형 목록으로 낮춘다.
- Docs는 질문에 맞는 문서를 찾게 한다. 입력·현재 조건·결과를 먼저 보여주고 소개와 장식을 뒤로 둔다.
- 상세는 읽는 흐름을 지킨다. 목차·코드·출처는 독서를 돕되 본문보다 더 눈에 띄지 않는다.

### 페이지별 설계

| 화면              | 제안                                                                                                                    | 완료 판단                                                                     |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 공용 헤더         | `최근 글 / 모든 글 / 주제 / 소개`를 후보로 검토. 기존 URL은 유지하고 언어별 이름을 맞춤                                 | 처음 온 사람이 검색 아이콘을 열지 않고 전체 문서로 이동 가능                  |
| 모바일 내비게이션 | 아이콘만 있는 하단 5개 탭 대신 상단 메뉴·검색을 우선안으로 비교. 유지한다면 짧은 텍스트 라벨과 safe-area를 보장         | 목적지 해석 가능, 하단 코드·링크를 가리지 않음. 삭제는 사용 빈도 검토 후 결정 |
| Feed              | 추천 글은 제목·문제·날짜/읽기 시간 중심. 동일 기본 썸네일은 생략하고 실제 도표·캡처가 있을 때만 작은 보조 이미지로 사용 | 390px에서 제목을 읽기 전에 반복 그림이 화면을 차지하지 않음                   |
| Docs              | 검색 패널의 목적 설명을 짧게. 결과 행의 `OPEN`과 중복 분류 배지 제거 후보. 활성 조건과 해제 경로는 접힌 필터 밖에 표시  | 본문 매치의 읽을 수 있는 요약, 현재 조건·결과 수를 바로 파악                  |
| Web·Mobile·UI/UX  | 동일한 허브 제목·설명·필터·목록 골격을 사용. 개성은 주제와 콘텐츠로 표현                                                | 제목·좌우 여백·카드 위계가 페이지마다 급변하지 않음                           |
| 내용이 없는 주제  | 준비 중임을 숨기지 않고 `모든 글 보기`를 직접 제공. 빈 Mobile을 주요 메뉴에 계속 둘지는 콘텐츠 계획과 함께 결정         | 막다른 설명만 남기지 않음. 기존 URL·외부 링크는 유지                          |
| 상세              | 상단 범위 요약·작성/수정 시점 제공, 본문 폭 조정, 모바일 접이식 목차 제공                                               | 긴 글에서 원하는 절로 이동·현재 절 확인·뒤로 이동 가능                        |
| 상세 하단         | 외부 출처와 내부 관련 글을 구분하고 중복된 더 읽기 영역은 축소                                                          | 무엇이 외부 근거이고 다음 내부 글인지 예측 가능                               |
| About             | 누구의 어떤 기록인지 짧게 소개하고 실제 공개 글로 연결                                                                  | 추상적인 자기소개·형식적 통계·빈 문의 기능 없이 신뢰 형성                     |

Backend 글이 있는 반면 현재 주요 메뉴와 Feed 주제 탭에 Backend가 보이지 않는다. `주제` 목록에서 실제 게시 콘텐츠의 분류를 노출하는 편을 우선 검토한다. 주제 추가를 새 독립 라우트나 빈 메뉴의 무조건적 증설로 해석하지 않는다.

### 조판·토큰의 초안

아래 수치는 시안 비교를 위한 출발점이며 기존 토큰을 아직 변경하지 않았다.

| 역할                  | 제안 범위                                                        | 확인할 점                                                                            |
| --------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 모바일 본문           | 16–18px, 행간 약 1.7–1.85                                        | 한국어·영문·인라인 코드가 섞인 문단을 실제 기기에서 비교                             |
| 데스크톱 상세 본문 폭 | 약 720–800px 후보                                                | 현재 944px 표본과 눈의 줄 이동을 비교. 한국어를 영어의 `ch` 기준만으로 판정하지 않음 |
| 상세 제목             | 모바일 28–34px, 데스크톱 36–44px 후보                            | 긴 기술 이름이 제목 한 단어만 다음 줄에 남기지 않는지                                |
| 목록 제목             | 모바일 18–20px 후보                                              | 메타를 줄이되 본문까지 작게 만들지 않음                                              |
| 보조 정보             | 12–14px 후보, 본문과 명확한 대비                                 | 날짜·읽기 시간을 읽기 어렵게 희미하게 만들지 않음                                    |
| 모바일 바깥 여백      | 16–20px 후보                                                     | 현재 일부 페이지의 40px보다 제목에 충분한 공간 확보                                  |
| 브랜드·상태           | 주황색은 브랜드·활성 상태·필요한 링크 강조                       | 장식용 주황색과 본문 링크/동작용 대비 색을 구분                                      |
| 카드·구획             | 행 구분선과 여백이 기본, 경계 카드 제한                          | 모든 섹션을 큰 둥근 패널로 감싸지 않음                                               |
| 모션                  | 상태 변경을 설명하는 짧은 opacity/transform, reduced-motion 존중 | 콘텐츠를 기다리게 하거나 큰 레이아웃 이동을 숨기지 않음                              |

중요 터치 동작은 프로젝트 목표로 44px 이상을 검토한다. [WCAG 2.2 AA의 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)은 예외·간격 조건을 포함한 24×24 CSS px 기준이며 44px를 AA 의무라고 설명하지 않는다. [Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)는 별도 320px/확대 검사로 확인한다. 코드의 내부 가로 스크롤 자체를 페이지 전체 overflow나 자동 WCAG 실패로 취급하지 않는다.

### 재사용과 도메인 경계

기존 [재사용 정책](docs-document-ui-reuse-policy.md)과 [ADR-0005](adr-0005-document-preview-card-boundary.md)를 유지한다. 하나의 거대한 `BlogCard`와 수십 개 variant prop으로 전체 화면을 통합하지 않는다.

| 계층                | 책임                                                                                                                  |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `packages/ui`       | Base UI 기반 Button·Input·Dialog·Collapsible 등 도메인 없는 동작·접근성. 블로그 데이터 조회나 콘텐츠 분류는 넣지 않음 |
| `shared`            | 간격·조판·색의 의미 토큰, 날짜·썸네일 표시 도구. 로컬/원격 출처는 사용자 정보로 복원하지 않음                         |
| `entities/document` | 제목·요약·읽기 시간·주제의 표시 계약, 의미 있는 썸네일 유무. Feed 미리보기와 검색 결과 행의 목적 차이는 유지          |
| `feature/search`    | 정제된 검색 문맥·하이라이트·입력·URL 상태. 전체 MDX/Shiki 렌더러를 검색 목록마다 실행하지 않음                        |
| `widgets`           | Feed 추천과 목록, Docs 검색/결과, 주제 허브, 상세 목차/본문의 조합                                                    |
| `app`               | 라우트·metadata·데이터 연결·loading 경계. 페이지 내부에 새 UI 전체를 다시 모으지 않음                                 |

모바일 목차는 기존 TOC 항목 모델과 ID를 재사용하되 표시 방식만 접이식으로 바꾼다. 코드 복사 시 실제 원문은 그대로 유지한다. 이미지 예압축·preload나 렌더링 파이프라인 재작성은 시각 개선과 분리한다.

### 적용 순서와 검증

1. **사용성 보완:** 검색 요약의 원문 기호 정리, 모바일 목차, 빈 주제의 다음 행동. 각각 회귀를 추가한다.
2. **시각 체계 비교:** Feed·Docs·상세의 데스크톱/390px 시안을 먼저 비교하고 조판·간격·이미지 정책을 합의한다. 합의 후 허브·About으로 확장한다.
3. **작은 구현 단위:** 의미 토큰 → 공용 표시 단위 → 화면 조합 순서로 반영한다. 기존 locale·query·필터·뒤로가기·스켈레톤 계약을 유지한다.
4. **독자 검증:** 아래 과제와 기기 검사를 수행하고 관측값으로 밀도·목차·내비게이션 정책을 조정한다. 시각 선호만으로 확정하지 않는다.

| 검증 과제                                   | 기록할 결과                                        |
| ------------------------------------------- | -------------------------------------------------- |
| 처음 온 독자가 React 관련 글 찾기           | 첫 클릭, 완료/실패, 헤맨 메뉴, 소요 시간           |
| 기억나는 키워드로 글 다시 찾기              | 입력부터 맞는 결과 선택까지의 단계, 요약 이해 여부 |
| 긴 글의 특정 절을 모바일에서 찾아 코드 복사 | 절 이동 성공, 복사된 원문 일치, 돌아갈 경로        |
| 결과 없음·빈 Mobile에서 다른 글로 이동      | 막힌 지점, 조건 해제·대체 링크 사용 여부           |
| 키보드·확대·가상 키보드·회전·다크모드       | focus 순서/복귀, 가림, reflow, 대비, overlay 잔존  |

처음에는 독자 3–5명과 과제형 관찰을 제안한다. 모집·실행하지 않았으므로 만족도·전환율·목표 달성률은 현재 결과가 아니다. 자동 검사는 320/390/768/1440px, light/dark, reduced-motion과 포커스·URL 유지 회귀를 포함한다. 본 작업의 16회 화면 확인은 이 전체 검사를 대신하지 않는다.

## 대안과 영향

- **장식 위주의 일괄 리뉴얼:** 첫인상 차이는 크지만 탐색·읽기 문제를 해결하지 못한 채 회귀 범위가 커진다. 우선안으로 택하지 않는다.
- **저널과 색인의 병행:** 브랜드는 유지하며 화면 목적별 밀도를 조정한다. 추천안이다. 콘텐츠 메타·query 상태를 유지하면서 단계별 비교가 가능하다.
- **문서 도구형 전체 통합:** 재방문 탐색에는 유리하지만 개인 기록의 개성과 발견 흐름이 약해질 수 있다. 향후 검색 중심 독자가 실제로 많을 때 재검토한다.

모바일 하단 바 제거, 상위 메뉴 교체, 공용 UI API 변경은 아직 결정하지 않았다. 선택 후 구조·책임이 실제로 달라지면 해당 결정만 별도 ADR로 남긴다. 현재 공용 Base UI를 바꾸거나 새 애니메이션 라이브러리를 도입할 이유는 확인하지 못했다.
