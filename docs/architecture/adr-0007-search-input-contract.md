# ADR-0007: 검색 입력 계약을 화면·URL·API에서 공유한다

## 상태와 범위

- 상태: 적용 중
- 대상: docs 헤더·본문 검색, `/docs?q=...`, `/api/search`
- 결정일: 2026-09-23
- 최종 검토: 2026-09-23
- 적용 위치: `feature/docs` 작업 트리. 운영 배포 검증과 구분한다.

## 배경

헤더에만 40자 제한이 있어 본문 검색과 직접 URL·API가 서로 다른 검색어를 처리했다. 반복 query는 Next 페이지에서 배열이 될 수 있어 문자열만 가정하면 실패한다. 한글 조합 중 자르거나 Enter 제출하면 입력이 끊길 수 있다.

## 결정

`shared/lib/search-query.ts`를 입력 계약의 원본으로 사용한다. 같은 q의 반복은 첫 값만 사용하며 첫 값이 비어 있어도 뒤 값으로 대체하지 않는다. 앞뒤 공백 제거·연속 공백 축소·NFC 정규화 후 최대 40 Unicode code point로 제한하고 잘린 끝의 공백도 제거한다. 빈 검색어는 전체 목록이다. UI 표시·API query는 대소문자를 보존하고 검색 비교에서만 소문자로 바꾼다.

입력 중에는 공백을 유지한다. IME 조합 중에는 길이 제한과 제출을 미루고 조합 종료 후 제한한다. HTML maxLength의 UTF-16 단위와 충돌하지 않도록 클라이언트 공통 훅을 사용하며 서버도 항상 같은 제한을 적용한다. 가족 이모지 등 여러 code point가 합쳐진 글자는 한 글자로 세지 않는다.

UI에서 생성하는 검색 URL은 정규화된 값 하나만 넣는다. 직접 입력한 URL을 강제로 redirect하지 않지만 표시·검색·후속 필터 링크에는 정규화된 값을 사용한다. 기존 API 응답 형태·검색 관련도·검색 결과 페이지네이션 보류는 유지한다.

## 대안과 영향

- 초과 입력을 400으로 거절하면 오류가 명확하지만 기존 헤더의 잘라내기 UX와 다르다. 모든 진입점에서 같은 유효 검색어를 사용하는 방식을 선택했다.
- UI만 제한하면 직접 URL·API가 우회하므로 서버 경계에서도 검사한다.
- 40자를 넘는 직접 URL/API 검색은 이전과 결과가 달라질 수 있다. API의 `query`는 실제 적용한 값을 반환한다.
- grapheme 단위 제한은 별도 정책으로 재검토할 수 있으나 이번에는 code point 단위로 명시한다. native IME·모바일 키보드 실제 기기 검증은 별도로 필요하다.
