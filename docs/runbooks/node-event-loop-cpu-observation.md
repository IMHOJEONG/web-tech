# Node.js CPU 작업과 이벤트 루프 콜백 관측

## 목적과 준비 조건

macOS 로컬 실험실에서 동기 CPU 작업이 타이머·TCP 수신 콜백을 늦추는지 비교합니다.
Node.js 24와 설치된 pnpm 의존성이 필요합니다. sudo·외부 서비스·비밀 환경변수는 필요하지 않습니다.
실험실 경로는 `/Users/coder/Desktop/project/labs/streaming-backpressure-lab`입니다.
공개 블로그 본문에는 이 경로·검사 연결을 표시하지 않습니다.

## 실행 순서

실험실 디렉터리에서 타입과 실제 실행을 확인합니다.

```sh
pnpm typecheck
pnpm test:event-loop
```

결과만 다시 보고 싶으면 다음 명령을 사용합니다. 각 조건 3회가 실행됩니다.

```sh
pnpm demo:event-loop
```

화면에서는 `pnpm dev`로 서버를 켜고 [이벤트 루프 실험실](http://127.0.0.1:3100/event-loop)에서
버튼을 누릅니다. 실행할 때마다 새 측정값을 표시합니다. 첫 화면의 링크로도 들어갈 수 있습니다.
수신자는 별도 실험 프로세스이며 송신자를 다시 별도 프로세스로 만듭니다.
고정된 스크립트만 실행하며 입력으로 명령·파일 경로를 받지 않습니다.

화면 회귀 검사는 서버가 켜진 상태에서 `pnpm test:event-loop:ui`로 실행합니다.
설치된 형제 web-tech 저장소의 Playwright·Chromium을 사용합니다. CLI 실험 검사는 브라우저에 의존하지 않습니다.
다른 포트는 `EVENT_LOOP_LAB_URL`, 화면 증거 디렉터리는 `EVENT_LOOP_UI_ARTIFACT_DIR`로 지정합니다.
CLI 검사 결과를 보관하려면 `EVENT_LOOP_ARTIFACT`에 JSON 파일 경로를 설정합니다.

## 기대 결과

200ms 계산 표본의 타이머·모든 data·end 실행이 CPU 종료 이후여야 합니다.
각 조건 3회에서 본문 16,384바이트와 고정 SHA-256이 같아야 하며 지연 측정기는 긴 정지를 잡아야 합니다.
0ms 조건의 정확한 실행 시각·data 횟수는 고정하지 않습니다. 20ms는 타이머 예약 기준입니다.
브라우저에는 같은 시간축의 비교 그래프와 전체 6회 표가 표시됩니다.

## 실패 대응과 복구

검사 실패를 무시해 성공으로 표시하지 않습니다. 송신자 시작·준비 응답, 본문, 콜백 시각,
샘플러 준비 개수·CPU 전/후 max를 순서대로 확인합니다. 다른 CPU 작업을 멈추고 재실행한
결과는 이전 실패와 별도로 보관합니다. 지연 검사의 기준을 낮춰 통과시키지 않습니다.
시작 시간 초과·실패 시 수신 소켓과 송신자를 정리합니다. 화면은 오류와 재시도 버튼을 표시합니다.
API 실행은 최대 15초이며 다른 실행이 진행 중이면 409로 응답합니다.
이 제한은 개발 서버 프로세스 안의 가드이며 분산 환경의 잠금은 아닙니다.
중단은 터미널의 Ctrl+C로 합니다. 실험은 파일·데이터베이스·운영 서비스를 변경하지 않습니다.
