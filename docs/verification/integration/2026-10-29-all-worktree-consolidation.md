## 재현 방법

원래 저장소에서 읽기 전용으로 등록·미커밋·인덱스·stash를 기록했다. 아래는 그 점검 범위를 재현하도록 10-29에 보완한 명령이다. Bash와 `--porcelain -z`를 지원하는 Git이 필요하다. 원시 출력에는 개인 경로·파일명이 포함되므로 로컬에서만 확인하고 저장소나 외부 기록에 복사하지 않는다.

```bash
set -e
git worktree list --porcelain
bash <<'BASH'
set -euo pipefail
inventory=$(mktemp)
trap 'rm -f "$inventory"' EXIT
git worktree list --porcelain -z > "$inventory"
while IFS= read -r -d '' field; do
  case "$field" in
    'worktree '*)
      wt=${field#worktree }
      printf '\nWORKTREE %q\nSTATUS (NUL delimited):\n' "$wt"
      git -C "$wt" status --porcelain=v1 -z --untracked-files=all
      printf '\nINDEX (NUL delimited):\n'
      git -C "$wt" ls-files --stage -z
      ;;
  esac
done < "$inventory"
BASH
git stash list --format=%H
```

NUL 구분 경로를 `git -C`에 그대로 전달하므로 공백·줄바꿈이 있는 경로도 분리하지 않는다. 등록 조회 또는 개별 명령이 실패하면 중단하며 실패한 작업 트리를 clean으로 판정하지 않는다. 임시 등록 목록만 만들고 종료 시 지우며 작업 파일·인덱스·stash는 변경하지 않는다. 각 `STATUS`가 비어 있는지와 이전 `INDEX`·stash 사본을 대조해야 한다. 이 조회만으로 원본/사본 해시 일치나 과거 HEAD 보존까지 증명하지는 않는다. 재실행은 그 시점의 등록 수·미커밋 상태를 보여 주며, 과거의 18곳 clean 결과를 소급 변경하지 않는다.

파일별 SHA-256, 실행 권한·심볼릭 링크, HEAD·논리 인덱스·Git 연결을 기록한 뒤 모든 165개 원본과 Git admin 정보를 저장소 밖 소유자 전용 폴더에 백업했다. 사본과 원본을 다시 해시 대조했다. 분석·복구 manifest와 원시 로그는 비공개 보관한다.

1. 현재 main과 다른 보존 참조의 실제 blob을 대조했다. 단순히 커밋 수나 파일명이 같다는 이유로 중복 판정하지 않았다.
2. 독립 검토에서 오래된 목차 조합·더 최신인 기록·진짜 새 관측을 구분했다. 오래된 NAS 워크플로와 ADR 번호를 최신 보존 구현 위에 덮어쓰지 않았다.
3. 고유한 공개 가능 부분만 현재 main 위에 작업별로 옮겼다. 원본을 요약한 경우 원시 로그 복사나 새 실행 검증으로 표시하지 않았다.
4. 전체 경로·HEAD·인덱스·원본/사본 해시를 다시 확인하고 복구용 로컬 참조 18개를 남겼다. 사용자 편집 중지 확인 후 승인된 55개 추적 경로만 `git restore --worktree`로 복원하고, 110개 미추적 경로만 검증된 비공개 사본에 남긴 뒤 원래 작업 트리에서 제거했다.
5. 전체 18곳을 다시 조사하여 미커밋 0개, HEAD·브랜치·Git 연결·논리 인덱스와 stash OID·순서 유지를 확인했다. ignored 파일·디렉터리는 삭제하지 않았고 전체 clean/reset도 사용하지 않았다.

새 커밋마다 실제 인덱스에 다음 검사를 적용하고 기존 훅을 유지했다.

```bash
pnpm format:staged:check
pnpm validate:docs --staged
pnpm exec commitlint
```

루트 `test:repo`와 동일한 14개 테스트 파일을 Node 24.22.1에서 실행했다. 최초 실행은 로컬 소켓 listen 권한으로 2개 실패했다. 허용된 환경에서 기대값·테스트 코드를 바꾸지 않고 전체를 다시 실행했다.

```bash

```

## 한계와 후속 작업

- 메인 화면·미디어의 일부 남은 변경은 현재 없는 세 컴포넌트와 비교 도구 파일을 참조했다. 작업 트리·보관 사본과 Git의 미참조 blob 1,031개를 제한된 이름 기준으로 검색했지만 해당 컴포넌트 원본을 찾지 못했다. 모든 디스크·과거 자료의 복구 가능성을 부정하는 완전한 포렌식은 아니다.
- 위 부분 구현, 개인 Figma 원본 기록, 미승인 자료와 오래된 합성 목차는 비공개 보관했다. 컴파일 가능한 기능이나 새 공개 설계 문서로 억지 커밋하지 않았다. 복구·재구성 후 별도 기능 검증이 필요하다.
- 승인형 NAS 도구는 이미 보존된 `81713c1` 쪽이 더 최신이었다. 옛 ADR-0022·Node 선택·배포 지침으로 회귀시키지 않았으며 실제 NAS 배포·승인 활성화는 하지 않았다.
- 옛 보고서 일부는 열린 PR #69~#73의 더 최신 기록으로 대체돼 있었다. 사본은 보존하지만 새 커밋으로 덮어쓰지 않았다.
- 원래 작업 트리는 각자의 기존 HEAD를 유지한다. 오래된 checkout이 최신 main의 파일 전체를 갖게 만든 작업이 아니며, 다음 개발은 필요한 최신 브랜치에서 시작해야 한다.
- 사본은 같은 Mac의 비공개 보관 자료다. 외부 장치 백업이나 저장소 전체 비밀정보 감사는 아니다.
- 새 커밋 push·PR·병합·배포는 실행하지 않았다. 마지막 증거 기록 커밋에는 문서 검사만 추가 적용하며 198개 실행은 명시한 소스 SHA 기준이다.
