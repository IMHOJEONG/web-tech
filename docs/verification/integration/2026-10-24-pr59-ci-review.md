### 자기 비교 재현

아래는 `includeDev=true` 정적 그래프다. 패키지 개수·edge 변경은 런타임 장애 개수가 아니다.

| workspace               | HEAD 기준 추가/제거/edge | 원래 main 16c51e9 기준 추가/제거/edge |
| ----------------------- | ------------------------ | ------------------------------------- |
| apps/docs               | 0 / 0 / 0                | 26 / 3 / 10                           |
| apps/docs-backend       | 0 / 0 / 0                | 51 / 21 / 30                          |
| apps/vuln-radar         | 0 / 0 / 0                | 147 / 42 / 5                          |
| apps/vuln-radar-backend | 0 / 0 / 0                | 51 / 21 / 30                          |
| packages/ui             | 0 / 0 / 0                | 3 / 2 / 2                             |

HEAD와 현재 lockfile은 SHA-256도 같았고, 원래 main의 lockfile은 달랐다. 이 문제는 과거 artifact가 당시 잘못 측정됐다는 증거가 아니라 **커밋 후 문서 명령의 비교 기준이 바뀌는 재현성 결함**이다. 분석 함수의 fixture 단위 테스트가 통과하는 것과 CLI가 올바른 Git 기준선을 선택하는 것은 별도 검사다. 현재 CI는 새 분석/CLI 도구의 main 대조 전체 실행을 호출하지 않아 이 결함을 차단하지 않는다.

### 추가 비차단 관측

Vercel 빌드 로그에 공용 `@web-tech/ui#build`의 backend origin/token 환경변수 선언 경고가 있었다. 공용 UI build는 두 값을 읽지 않고 vuln-radar 태스크는 앱별 `turbo.json`에서 선언한다. 이 로그만으로 프록시 토큰 누락·API 장애·유출을 단정하지 않는다. 경고 제거를 위해 비밀값을 공용 UI/global env에 확장하는 조치는 하지 않는다.
