# 비공개 Git 콘텐츠 공급·운영 전환 검증

## 대상과 조건

- 날짜: 2026-11-17, Asia/Seoul
- 기준: main `6b807f26fd878af38bdc144fdfe8f4af02585281` 위 별도 로컬 작업 트리
- 콘텐츠: 기존 KAN-80 Preview가 사용한 고정 Git SHA. 글 17개·자산 15개는 현재 공개 main과 bytes가 모두 동일하다.
- 환경: macOS, Node 24.22.1, pnpm 12.14.0, 설치된 Next.js 16.4.3
- 범위: 코드·합성 회귀·기존 공개 파일의 로컬 재검수와 스냅샷 준비. Production·NAS·원격 콘텐츠 변경은 제외한다.

## 재현 방법

저장소 루트에서 프로젝트 pin의 Node·pnpm으로 실행한다.

```sh
pnpm --filter docs test:content
pnpm --filter docs test:lib
pnpm --filter docs typecheck
```

실제 콘텐츠 준비·Next 출력 검사는 [운영 절차](../../runbooks/docs-private-git-content.md#2-로컬-준비-검사)를 따른다. 승인된 검수 목록과 bare Git 사본은 저장소 밖에 보관했다. 원시 원문·응답·개인키를 이 보고서에 포함하지 않는다.

실패한 중간 URL 검사는 파일명 대신 slug만 바꿨기 때문에 canonical 경로가 그대로였던 테스트 입력 오류다. 실제 canonical 파일 경로를 바꾸도록 수정했으며 URL 집합 일치 조건은 유지했다. 초기 상대 이미지 참조 거절은 기존 `../../../public/...` 작성 방식과 새 자산 수집기의 불일치였다. 기존 렌더러의 안전한 정규화 함수를 공유해 원문 변경 없이 보완했다.

공개 패턴 검사에서 테스트용 고정 토큰 문자열과 인증정보를 포함한 합성 URL 리터럴도 거절됐다. 실제 비밀값은 아니지만 규칙을 면제하지 않고 동일 입력을 실행 시 조합하도록 바꿨다. 새 문서와 수정한 목차의 실제 공개 승인은 별도로 남아 있다.

최초 격리 런타임 검사는 목록 첫 페이지에 전체 글이 있어야 한다고 잘못 가정해 실패했다. 기존 페이지네이션의 모든 페이지를 조회해 승인된 17개 URL의 합집합을 확인하도록 절차를 바로잡았다. 글·검사 대상을 줄이지 않았다. 출력물 검증이 통과해도 비정상 종료한 빌드를 성공한 release로 격상하지 않는다.

## 한계와 후속 작업

로컬 검수 목록은 아직 비공개 Git 커밋에 없다. 실제 읽기 전용 deploy key의 원격 fetch·Vercel Preview/Production·PNA 이전·코드 저장소 원문 제거·CI 비밀정보 공급은 미검증이다. 인증 준비 함수를 합성 실행기로 검사한 결과를 실제 deploy-key 인증 성공으로 간주하지 않는다.

NAS 설정을 지우거나 운영 컨테이너를 종료하지 않았다. 기존 미커밋·stash와 열린 PR 작업도 수정하지 않았다. 새 코드·문서의 공개 승인·커밋·푸시·병합은 별도다. 원시 자료와 실제 원문의 공개 artifact를 추가하지 않았다.

Next.js의 보안 종료를 해소하고 표준 빌드의 exit 0을 확인해야 인증된 Preview·운영 전환을 진행할 수 있다. 해당 종료 메시지가 안내하는 자동 조치는 실행하지 않았다. 플랫폼 보안 패치 작업과의 중복 여부를 먼저 확인한다.

## 2026-11-18 인증된 Preview 검증

사용자는 Preview 검증과 기존 공개 글 17개·자산 15개의 검수 목록에 한정된 비공개 커밋·푸시를 승인했다. 원문 bytes를 바꾸지 않고 `.publication-review.json` 한 파일만 비공개 콘텐츠 커밋 `8e53eabbfcaa139a1b9b66af4647aa230f8adab1`로 반영했다. 앱의 lock은 이 SHA로만 갱신했으며 공개 코드 저장소에는 커밋·푸시하지 않았다.

대상은 [보호된 Preview](https://web-tech-8twu38g0n-hojeong-ims-projects.vercel.app/ko/docs), 배포 `dpl_7rPEFFT1FGJN1yD4XBLo2GmQzaDc`다. 앱은 main `a7e095c5` 위 미커밋 전환 코드의 격리 사본이며, 이 배포를 원격 앱 커밋의 CI 결과로 표현하지 않는다. Node 24.x·pnpm 12.14.0·Next 16.4.6, Chromium 1280×900·390×900에서 확인했다. 기존 `data/category` 원문 디렉터리 없이 배포했고 읽기 전용 deploy key의 실제 fetch와 고정 리비전의 검수 목록을 사용했다. 로컬 제출 사본의 파일 목록·해시 집계 SHA-256은 `135d61b2db80955ba96f467e4d040406d8d03970c5eb18c25d8672e7c51a5887`이다. 키·환경 파일·Git 객체·원시 로그는 제출 사본에 넣지 않았다.

실행은 [인증된 Preview 절차](../../runbooks/docs-private-git-content.md#3-인증된-preview-빌드)를 따른다. 빌드는 `pnpm --filter docs build`이며 키는 `--build-env DOCS_PRIVATE_CONTENT_SSH_KEY`의 이름만 인수에 주고 제한된 부모 환경에서 전달했다. 실제 값이 들어간 명령이나 인증 상태는 재현 예시·문서·외부 기록에 남기지 않는다.

중간 실패는 보존한다. 첫 Preview는 격리 사본에서 다른 workspace manifest가 빠져 frozen-lockfile 검사로 실패했다. 다음 Preview는 기존 E2E의 공개 예제 코드 타입 참조가 누락되어 실패했다. 원본 manifest와 참조 예제 코드만 보충했으며 lockfile 재생성·타입 검사 생략은 하지 않았다. 브라우저 첫 시도는 목록이 아닌 다른 카드의 속성을 선택한 검사 오류였다. 실제 목록의 문서 Link로 선택자를 바로잡았으며 문서 수·본문·검색·timeout 기준을 낮추지 않았다. 로컬 콘텐츠 회귀의 최초 EPERM은 샌드박스의 localhost 포트 제한으로, 승인된 재실행에서 47개 모두 통과했다.

원시 빌드/런타임 로그·응답·브라우저 인증·검사 도구와 원본 파일별 해시 목록은 저장소 밖 비공개 위치에만 보관한다. 이 섹션은 정제된 로컬 기록이며 공개 검수 해시를 임의 갱신하지 않았다. PNA 이전·공개 원문 삭제·CI 인증 분리·운영 전환은 이번 검증에 포함되지 않았고 별도 판단이 필요하다.

마감 대조에서 기존 변경 29개 중 의도한 lock·ADR·runbook·보고서·worklog 5개만 달라졌고 나머지 24개는 bytes가 같았다. 다른 조사 트리 3개·원래 기록 5개도 동일했다. 세 트리의 HEAD·status·인덱스와 기존 stash 10개가 시작과 같았다. 인덱스를 바꾸지 않은 작업 사본 문서 검사·코드 공개 패턴 검사·변경 파일 포맷·diff 검사는 통과했다. [KAN-80](https://web-tech-service.atlassian.net/browse/KAN-80)의 기존 3열 표와 [Confluence 후속 구역](https://web-tech-service.atlassian.net/wiki/pages/viewpage.action?pageId=65817&focusedCommentId=18415624)을 갱신·재조회했으며, 운영 전환이 남아 Jira는 진행 중으로 유지했다.
