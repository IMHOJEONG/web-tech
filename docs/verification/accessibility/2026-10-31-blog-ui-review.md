# 운영 블로그 UI·탐색·읽기 점검

## 대상과 조건

- 검증일: 2026-10-31 KST. 주 측정 저장 시점 12:20 KST.
- 대상: 공개 `https://heap-forge.app/ko/` 운영 화면. 실제 배포 SHA와 이 보고서의 로컬 base가 일치하는지는 확인하지 않았다.
- 로컬 문서 기준: main `7b40457d7bceab051196a0fdd658a4b792b41340`에서 분리한 `codex/docs-ui-review-20261031`. 앱 코드 변경 없음.
- 도구: Node.js 24.22.1, Playwright Chromium 151.0.7922.34. 데스크톱 1440×1000 / 모바일 에뮬레이션 390×844, light, reduced-motion. 뷰포트별 새 context, 각 경로 새 page, 폰트 준비 후 약 1.8초 대기.
- 표본: 8개 URL × 2개 뷰포트의 16회 GET. Browser Use에서도 별도 1920×824 / 390×844 화면과 긴 Brotli 글을 읽기 전용 점검했다.
- 원시 캡처·전체 관측 JSON·임시 probe는 저장소 밖 로컬 전용 보관. HAR·쿠키·인증 헤더·비공개 초안은 수집/업로드하지 않았다. 이 문서는 필요한 측정과 한계만 정리한 공개 검토 전 로컬 보고서다.

## 재현 방법

실행한 로컬 명령은 다음과 같다. probe는 이번 작업의 임시 파일이므로 다른 환경에 이미 설치돼 있다고 가정하지 않는다.

```sh
# 임시 점검 스크립트 실행. 공개 URL만 조회하며 사이트를 변경하지 않는다.
node /tmp/blog-ui-review-20261031.cjs
node /tmp/blog-ui-followup-20261031.cjs
```

주 probe는 `page.goto(..., { waitUntil: 'domcontentloaded' })`, `document.fonts.ready` 후 다음을 측정했다.

```js
document.documentElement.scrollWidth - innerWidth;
element.getBoundingClientRect().top + scrollY;
getComputedStyle(element).fontSize;
```

카드 측정은 `main`의 문서 링크 중 `h2`/`h3`가 있는 첫 링크를 선택했다. 따라서 Feed는 추천 `h1` 카드가 아니라 **최근 글 첫 카드의 상단**이고, 일반 색인은 **첫 카드 컨테이너 상단**이다. 제목 baseline·콘텐츠 표시 시점·LCP·CLS 측정값이 아니다. Web의 다른 카드 마크업은 이 선택자로 수집하지 않았으므로 누락을 글 없음으로 해석하지 않는다.

Browser Use는 공개 내비게이션, React 검색, Brotli 글의 목차·코드·다음 읽기를 확인했다. 추가 probe는 같은 검색 결과의 표시 문장과 긴 글의 visible TOC·`pre.clientWidth/scrollWidth`를 확인했다. 추가 실행은 sandbox의 Chromium 실행 권한 오류로 한 번 실패했고 승인된 재실행에서 완료했다. 이 실행 환경 오류를 사이트 장애로 집계하지 않았다.

### 보존할 장점과 코드 대조

- 카드 전체 링크, 제목·요약·읽기 시간, 검색 결과 수·페이지네이션, 주제 필터가 실제 존재한다. 새로 없는 기능처럼 재구현하지 않는다.
- 전체 페이지 가로 스크롤 문제가 이번 표본에서는 재현되지 않았다. 과거 10-14 보고서의 큰 목록 시작 위치를 현재 문제로 다시 인용하지 않는다.
- 데스크톱 목차·코드 복사 표시·외부 출처·관련 문서는 독서 흐름에 유용하다. 실제 복사 성공 여부는 이번에 검사하지 않았다.
- 로컬 base의 `article-content-layout.tsx`는 TOC aside에 `hidden lg:block`을 사용한다. `search-preview.ts`는 원문 일부를 자르고 HTML escape/highlight하며 Markdown-to-text 처리를 하지 않는다. 운영 관측과 부합하지만 배포 SHA를 대조하지 않아 동일 실행 코드를 확정하지 않는다.

## 한계와 후속 작업

- 휴리스틱·화면 기반 검토다. 실제 고객 만족도·이탈률·전환율, Core Web Vitals나 지각 로딩 속도를 측정하지 않았다.
- 한국어·light·Chromium 중심 표본이다. 영어, dark, Safari/Firefox, 실제 iOS/Android, 320px·400% 확대, 가상 키보드·회전, VoiceOver/NVDA, 전체 키보드 동선은 미검증이다.
- 문서 개수와 첫 카드 위치는 당시 게시 내용·캐시·폰트·뷰포트에 따라 달라질 수 있다. 사용자별 p75나 품질 점수로 일반화하지 않는다.
- 두 번째 긴 글의 19,948px와 Browser Use 약 19,946px 차이는 별도 세션 관측이다. 픽셀 단위 재현성을 주장하지 않는다.
- 원시 캡처와 probe는 로컬 임시 자료다. 공개 저장소·Jira·Confluence에 첨부하지 않았다. 승인된 정제 증거 업로드와 보관 정책은 별도 검토한다.
- 다음은 검색 요약·모바일 목차 우선 보완, Feed/Docs/상세 시안 합의, 3–5명 과제형 관찰이다. 세부 순서는 [설계안](../../architecture/docs-blog-redesign-proposal.md)을 따른다.
