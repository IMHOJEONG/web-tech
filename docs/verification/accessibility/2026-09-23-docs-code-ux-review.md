# 블로그 코드와 UI/UX 개선 상태 점검

## 대상과 조건

- 검토일: 2026-09-23 KST, `feature/docs`의 `d8e5a7a`.
- 이전 접근성 검증 문서를 독립 커밋한 뒤 docs production 빌드를 다시 실행했다. 앱 소스는 `4f5b0bb` 이후 변경하지 않았다.
- 원격 콘텐츠·Better Stack 전송을 끄고 로컬 공개 문서 10개를 사용했다. Node 24.12.0, Next.js 16.3.4, headless Chromium.
- 이번 작업은 분석과 현황 확인이다. 아래 개선 후보는 구현하지 않았다.

## 재현 방법

[로컬 production 검증 명령](2026-09-23-deployed-shell.md#로컬-production-후속-검증)과 같은 환경 변수로 `pnpm --filter docs build`를 실행하고, `next start --hostname 127.0.0.1 --port 3116`으로 확인했다.

다음 순서로 재현한다.

1. `/ko/feed`, `/ko/docs`, `/ko/web`, `/ko/mobile`, `/ko/ui-ux`, `/ko/about`을 390px·1280px로 열어 본문 로딩 완료 후 `main`, `h1`, 페이지 가로 넘침을 확인한다.
2. 로컬 문서 10개인 `/ko/docs?page=2`에서 비활성 표시된 다음 링크에 키보드 포커스를 두고 Enter를 누른다. 유효한 마지막 페이지는 2인데 주소는 `?page=3`으로 이동한다.
3. `/en/docs?q=no-match-review-20260923`의 제목을 확인한다.
4. `/ko/docs`의 본문 검색과 헤더 검색에 각각 80자를 입력해 입력값 길이를 비교한다.
5. 원격 목록을 끈 `/ko/ui-ux`에서 카드 제목과 실제 목적지를 확인한다.

이번 자동 관측 명령은 `mise exec -- node /tmp/docs-ui-review.ts`였다. 임시 스크립트는 저장소에 포함하지 않았으며 위 절차로 직접 재현할 수 있다.

## 결과와 증거

빌드·콘텐츠 16개 검증·TypeScript·정적 페이지 28개 생성이 통과했다. 12개 화면 조합은 `main` 1개, `h1` 1개, 문서 전체의 가로 넘침 없음으로 관측됐다. 이는 내부 잘림·모든 breakpoint·기기 접근성까지 통과했다는 뜻은 아니다.

## 한계와 후속 작업

- 카드·뉴스레터·About 등 반영 상태는 현재 소스와 표본 화면을 대조한 결과이며, 과거 Figma 시안의 픽셀 일치 검사가 아니다.
- 원격 문서 수에 따라 UI/UX 예시 카드 개수는 달라진다. 로컬 기준 5개를 운영 사이트 전체에 일반화하지 않는다.
- 운영 CSS 누락은 [별도 보고서](2026-09-23-deployed-shell.md)의 미해결 항목이다. 로컬 빌드 통과로 배포 문제를 닫지 않는다.
- 후속 순서: 운영 CSS 검증 → 비활성 페이지 이동 → 빈 상태/번역 → UI/UX 실제 문서 구성 → 검색 정책/구조 분리.
- 배포 검증 설정이 `/tmp`에 있어 재사용이 어렵다. 공개 페이지 읽기만 수행하는 저장소 소유 production/배포 smoke 설정과 CSS 토큰 assertion을 추가하는 것이 권장된다.
- 실기기, 음성 낭독, 전체 사이트 명암 대비와 성능 부하는 미검증이다. 이번 요청에서는 앱 코드 수정·배포를 하지 않았다.
