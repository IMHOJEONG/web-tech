# ADR 작성과 상태 관리

## 목적과 적용 범위

모노레포에서 구조에 영향을 주는 결정을 선택 이유와 함께 보존한다. ADR은 결정 하나당 한 페이지이며, 구현 기록(worklog)이나 현재 기능 설명(policy)을 복제하지 않는다. 코드 수정마다 작성하는 문서는 아니다.

## 작업 중 판단 순서

1. 작업 전 [설계 목록](../architecture/README.md)에서 해당 영역의 적용 중인 ADR을 찾는다. 충돌하는 결정이 있으면 그대로 구현하지 않고 변경 필요성을 판단한다.
2. 구조, 공개 URL/API/데이터 계약, 캐시·보안 경계, 공용 컴포넌트의 책임, 배포/운영 모델 중 장기적으로 영향을 주는 선택이 있는지 확인한다.
3. 실질적인 대안과 장단점이 있는 새 선택이면 [ADR 템플릿](documentation-templates.md#adr)을 사용해 결정당 한 파일을 작성한다. 결정이 아직 확정되지 않았다면 상태를 `제안`으로 둔다.
4. 기존 결정을 뒤집으면 새 번호의 ADR을 만들고 이전 문서는 본문을 다시 쓰지 않은 채 상태·대체일·후속 링크만 변경한다. 새 ADR도 대체 대상에 링크한다.
5. 설계 결정을 하지 않은 버그 수정, 문구 변경, 기존 정책의 구현·테스트 보강은 worklog/verification에 기록한다. ADR 미작성 사유만을 위한 별도 문서는 만들지 않되, PR/마감의 검토 입력란에는 `기존 결정 유지` 또는 `해당 없음`과 이유 한 줄을 남긴다.

번호는 `docs/architecture/adr-NNNN-주제.md`에서 저장소 전체에 순서대로 부여하고 재사용하지 않는다. 앱별 대상은 본문에 명시한다. 과거 커밋의 모든 변경을 소급해서 ADR로 만들지는 않는다.

## 매 작업의 검토 지점

| 시점      | 남길 판단과 근거                                                                                                                                               |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 착수      | 관련 ADR 번호·현재 상태·유지할 계약을 확인한다. 현재 checkout과 main 기준을 혼동하지 않는다.                                                                   |
| 구현      | 기존 결정의 구현 오류인지 새 선택인지 구분한다. 계약 구현 오류는 회귀로 바로잡으며 과거 결정을 오류에 맞춰 바꾸지 않는다.                                      |
| PR/마감   | PR의 `ADR 검토`에 검토한 번호와 `기존 결정 유지 / 새 결정 / 전체·부분 대체 / 해당 없음` 및 이유 한 줄을 적는다. 로컬-only 작업도 worklog에 같은 판단을 남긴다. |
| 병합/배포 | 확인한 main SHA·배포·기능 검증을 별도 단계로 상태/범위와 목차에 연결한다. 운영 미검증을 성공으로 바꾸지 않고 과거 verification도 보존한다.                     |

현재 [PR 템플릿](../../.github/pull_request_template.md)과 루트 `AGENTS.md`가 이 검토를 요청하며 `CLAUDE.md`는 같은 지침을 참조한다. 저장소 회귀는 템플릿의 검토 입력란·지침 연결과 이번 부분 대체 링크를 확인한다. 모든 PR 본문의 작성을 서버에서 강제하거나 코드의 의미와 ADR을 자동 비교하는 기능은 아니다. ADR 고유 번호·상태 전체 검사와 required checks 설정은 별도 후속이다.

## 일부 결정만 대체하는 경우

기존 ADR의 일부 책임만 바뀌면 전체 문서를 `대체됨`으로 표시해 나머지 결정을 무효화하지 않는다.

- 이전 ADR은 `적용 중`을 유지하고 상태/범위에 `후속 결정(부분 대체)` 링크와 `부분 대체 범위`, 계속 유지되는 책임을 명시한다. 당시 결정 본문은 보존한다.
- 후속 ADR에는 `부분 대체 대상` 역링크와 변경/유지 경계를 명시한다. 이미 후속 ADR이 그 결정을 담았다면 같은 결정을 새 번호로 복제하지 않는다.
- 목차에도 부분 대체를 표시한다. 연결을 보완한 날짜와 실제 결정일을 구분하고 뒤늦은 링크 수정일을 과거 결정일로 바꾸지 않는다.

현재 예시는 [ADR-0009](../architecture/adr-0009-docs-web-push-experiment.md)와 [ADR-0015](../architecture/adr-0015-explicit-offline-article-snapshots.md)다. Worker의 fetch·오프라인 캐시 책임만 후속 결정으로 바뀌고 구독·발송·접근 제한은 유지된다.

## 상태와 유지보수

- `제안`: 선택을 검토 중이며 현재 정책을 대체하지 않는다.
- `적용 중`: 결정이 채택되어 현재 구현과 일치한다.
- `대체됨`: 다른 ADR이 이 결정을 바꿨다. 후속 ADR 링크가 필수다.
- `폐기`: 제안을 채택하지 않았거나 결정 자체가 철회됐다. 이유를 짧게 남긴다.

승인 이후의 배경·결정·대안 설명은 당시 판단의 기록으로 남긴다. 사실 수정이나 링크 보완은 가능하지만, 결정을 바꾸려면 새 ADR을 만든다. [architecture 목록](../architecture/README.md)은 적용 중인 결정과 대체된 결정을 구분한다. 관련 정책 문서는 현재 규칙을, ADR은 그 규칙을 선택한 이유를 설명한다.
