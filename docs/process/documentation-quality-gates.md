# 문서 품질 검사와 증거 보관

## 적용 범위

대상은 모노레포의 `docs/` 운영 문서입니다. `docs/examples/`의 예제와 블로그 원문은 제외합니다. 상태는 적용 중이며 최종 검토일은 2026-09-23입니다. 문서 작성 형식은 [템플릿](documentation-templates.md)을 따릅니다.

## 커밋과 포맷

기존 pre-commit/pre-push의 전체 `prettier --write`를 제거했습니다. pre-commit은 스테이징된 Git blob을 검사만 하며 commit-msg의 commitlint는 유지합니다. pre-push에는 포맷 작업을 두지 않습니다.

```sh
pnpm format:staged:check
pnpm validate:docs --staged
pnpm test:repo
pnpm exec simple-git-hooks
```

마지막 명령은 훅 설치/갱신입니다. 포맷 실패 시 의도한 파일만 `pnpm exec prettier --write 경로`로 수정하고 diff를 검토하여 다시 스테이징합니다. 부분 스테이징 파일은 사용자 작업까지 포함되지 않도록 재검토합니다. 훅은 작업 트리나 인덱스를 수정하지 않습니다. 기존 `pnpm format`은 명시적으로 요청한 전체 포맷용이며 훅에서 사용하지 않습니다.

## 문서 변경 검사

- 새 운영 문서: H1 제목, 역할별 필수 섹션, 상대 링크, 상위 경로 README의 직접 링크를 검사합니다. README는 역할별 섹션 검사에서 제외합니다.
- 기존 문서: 비교 기준에 이미 있던 위반은 그대로이면 차단하지 않습니다. 새 깨진 링크와 기존 필수 섹션 제거 등 추가 위반은 실패합니다.
- 삭제된 링크 대상은 변경되지 않은 참조 문서에서도 검사합니다.
- fenced code 및 inline code 속 예시 링크는 제외합니다. 외부 URL, 같은 문서 anchor의 실제 유효성은 검사하지 않습니다.
- 일반 inline Markdown 링크와 reference 정의를 검사합니다. MDX 표현식 및 HTML href 같은 모든 문법을 완전하게 파싱하는 도구는 아닙니다.
- 목차는 자동 덮어쓰지 않습니다. 새 문서가 상위 README 어디에도 연결되지 않으면 실패합니다.

CI는 PR base 또는 main push의 이전 커밋을 기준으로 HEAD를 검사합니다. 로컬 기본값은 HEAD 대비 인덱스입니다.

```sh
pnpm validate:docs --base origin/main
```

이 명령은 `origin/main`부터 HEAD까지의 커밋된 변경을 검사하며 미커밋 작업은 보지 않습니다. 원격 기준 갱신은 별도 `git fetch`가 필요합니다. 자동 훅은 우회될 수 있으므로 GitHub에서 `Documentation delta checks`를 필수 상태 검사로 지정하는 것은 별도 저장소 관리 작업입니다.

## 정책 상태와 검토일

새 architecture 문서는 상태와 범위 아래에 `상태`, `대상`, `최종 검토`를 기록합니다.

- 제안: 아직 적용되지 않은 후보.
- 적용 중: 실제 채택된 정책.
- 보류: 실행하지 않기로 잠정 결정한 안.
- 폐기: 더 이상 따르지 않는 정책. 대체 문서 링크를 남깁니다.

검토일은 YYYY-MM-DD 형식의 실제 날짜이며 단순 오탈자 수정마다 갱신하지 않습니다. 상태 전환, 주요 버전 변경, 보안·운영 전제 변경 시 재검토합니다. 기존 정책은 관련 작업 때 점진적으로 템플릿으로 전환합니다.

### 문서 역할별 상태 해석

| 역할           | 현재 상태 관리 기준                                                                                                               |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| ADR            | `제안 / 적용 중 / 대체됨 / 폐기`를 사용합니다. 대체된 문서는 후속 ADR·대체일을 기록하고 당시 결정 본문을 보존합니다.              |
| 일반 설계·정책 | 위의 `제안 / 적용 중 / 보류 / 폐기`를 사용합니다. 일부만 적용했다면 적용 범위와 남은 작업을 함께 적습니다.                        |
| Runbook        | 실행 대상·준비 조건과 마지막 실제 검증 결과를 연결합니다. 절차가 존재한다는 이유로 실행 성공을 표시하지 않습니다.                 |
| Verification   | 당시 날짜·커밋·환경의 `통과 / 실패 / 미검증`을 보존합니다. 이후 성공했어도 과거 실패 결과를 덮어쓰지 않고 후속 검증을 연결합니다. |
| Worklog        | 당시 변경과 검증 기록입니다. `Next`는 당시 계획이며 최신 TODO나 운영 상태의 원본이 아닙니다.                                      |
| TODO           | 미완료·완료와 완료 근거를 관리합니다. 구현, 코드 병합, 배포 검증은 각각 구분합니다.                                               |

`적용 중`과 `배포 검증 완료`는 다릅니다. 적용 브랜치·커밋이나 PR, 확인한 환경을 남기고 확인하지 않은 소비 앱·배포 환경은 미검증으로 표시합니다. 새 ADR의 상태는 [ADR 관리 규칙](adr-management.md)을 우선합니다.

상태 변경 시에는 다음 순서로 확인합니다.

1. 현재 코드·병합 커밋·검증 보고서를 근거로 적용 범위를 확인합니다. 판단할 근거가 없으면 상태를 임의로 승격하지 않습니다.
2. 원본 정책의 상태·범위·필요한 검토일을 수정합니다. 결정 자체가 바뀌면 기존 ADR을 다시 쓰지 않고 후속 ADR을 만듭니다.
3. 역할별 목차와 관련 TODO·후속 문서 링크를 맞춥니다. 작업 기록에는 변경한 상태와 근거, 미확인 범위를 남깁니다.
4. `pnpm validate:docs --staged`로 문서 구조·링크를 검사하고 실제 상태와의 일치는 사람이 확인합니다. 현재 검사 도구가 구현·배포 상태까지 자동 판정하지는 않습니다.

## 검증 증거 보관

- 새로 추가하거나 수정하는 artifact는 파일당 1 MiB 이하로 유지합니다. 기존 초과 파일이 그대로인 경우는 차단하지 않습니다.
- JSON은 구문을 확인합니다. 파일 분할이나 압축으로 용량 제한을 우회하지 않습니다.
- 대용량 trace/video는 접근 제어된 CI artifact 또는 별도 스토리지에 둡니다. 보고서에는 위치, 실행 ID, 생성일, 만료일과 필요하면 체크섬을 남깁니다.
- 임시 trace는 기본 30일 후 삭제를 검토합니다. 기준선·회귀 증거는 다음 기준선 검증까지 유지하고 제거 사유를 기록합니다. 자동 삭제 작업은 추가하지 않았습니다.
- 수집 전에 토큰, 쿠키, 인증 헤더, 사용자 식별 정보와 비공개 응답 본문을 제외합니다. 보고서로 설명 가능한 최소 데이터만 보관합니다.
- 검사는 명백한 private key와 긴 literal Bearer 토큰만 추가 탐지합니다. 모든 비밀정보를 찾아준다고 보장하지 않으며 오류 출력에도 비밀값을 포함하지 않습니다.
- 이미 유출된 비밀값은 파일 삭제만으로 해결되지 않습니다. 먼저 자격증명을 폐기/교체하고 별도 사고 대응을 진행합니다.
