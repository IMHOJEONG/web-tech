# Jira 이슈 추적과 저장소 문서 연결

- 기준 검토: 2026-10-20. 매 작업 기록 의무와 Jira 댓글 표준 형식은 PR #47에서 검토하며 main 전파에는 PR 병합이 필요하다.

- [Jira 에픽 KAN-1](https://web-tech-service.atlassian.net/browse/KAN-1): 운영 검증과 공용 플랫폼 후속 개선.
- [Confluence 개발·운영 안내](https://web-tech-service.atlassian.net/wiki/spaces/~5d12f74be69c1c0c88af2afa/pages/65817/web-tech+Jira): 개인 공간 `임호정`에 도구별 역할, 앱 분류, Jira 과제와 저장소 문서 입구를 게시했다. 기존 페이지·공간 권한은 변경하지 않았고 별도 공용 공간은 만들지 않았다.
- 토큰·계정 비밀번호·인증 헤더는 저장소나 이슈에 기록하지 않는다. 연결 도구의 계정 권한을 사용한다.

## 역할과 원본

- Jira는 등록된 작업의 진행 상태, 우선순위, 완료 조건, 보류 사유의 원본이다.
- 저장소 `docs/architecture/`, `docs/runbooks/`, `docs/verification/`는 기술 결정·절차·실행 증거의 원본이다. Jira에서 해당 문서와 커밋을 연결한다.
- [TODO](../todo/todo.md)는 탐색용 이슈 목차와 아직 이전하지 않은 후보를 유지한다. Jira로 옮긴 작업의 상태를 별도 수동 복제하지 않는다.
- Confluence는 프로젝트 배경·논의·운영 안내와 배운 개념·운영 교훈을 주제별 지식 문서로 제공한다. 작업 댓글은 진행 이력으로 구분한다. 구현에 결합된 기술 결정·절차·검증 결과의 원본은 저장소에 두고 전체 내용을 복제하거나 Jira 상태를 수동으로 재작성하지 않는다.
- 오래된 TODO 체크박스만 보고 미구현을 판단하지 않는다. 코드·병합·검증 결과와 대조하고 중복 이슈를 만들지 않는다.

## 작업 기록과 배운 지식의 분리

2026-11-19 사용자 요청으로 구분을 보강한다. 작업 기록은 무엇을 언제 어떤 조건에서 실행했는지, 지식 문서는 다음에도 어떤 기준으로 판단할지를 설명한다. Confluence 댓글에 실행 결과만 남긴 뒤 배운 지식도 정리됐다고 보고하지 않는다.

| 위치                                      | 주된 질문                                    | 남길 내용                                        |
| ----------------------------------------- | -------------------------------------------- | ------------------------------------------------ |
| Jira·worklog·진행 댓글                    | 이번에 무엇을 했고 무엇이 남았는가?          | 기준 SHA·실행 결과·실패·완료 조건·보류 범위      |
| Confluence 주제별 지식 문서               | 이 개념은 무엇이고 다음에는 어떻게 판단할까? | 개념·선택 이유·프로젝트 교훈·재사용할 판단 기준  |
| 저장소 ADR·runbook·verification·knowledge | 실제 구현·정책·절차·근거는 무엇인가?         | 코드에 결합된 원본·재현 명령·측정 조건·정제 증거 |

마감마다 다음 조건을 확인한다. 새로운 개념을 이해해야 해결했거나, 같은 오해가 반복되거나, 다음 운영 조치의 판단 기준이 달라지거나, 실패에서 재사용할 교훈을 얻었다면 지식 승격 대상이다. 단순 카피 수정·정기 재검사 등 새 교훈이 없으면 worklog Notes에 이유만 기록하고 새 페이지를 강제하지 않는다.

승격 순서:

1. Confluence의 같은 주제를 검색한다. 기존 문서를 갱신할 수 있으면 새 페이지를 만들지 않는다. 실제로 독립된 주제만 분리한다.
2. 제목은 날짜·티켓 번호보다 독자가 찾을 개념·질문으로 정한다. 운영 안내 하위의 주제 페이지로 두고 안내·지식 색인에서 찾을 수 있게 연결한다. 진행 댓글은 본문을 대신하지 않는다.
3. 개념 → 프로젝트 사례 → 판단 기준 → 주의점 → 원본 근거 순으로 작성한다. 대상·최종 검토일·적용/실험/제안/미검증 범위를 밝힌다. 과거 조회의 성공을 현재 운영 상태로 일반화하지 않는다.
4. 공식 자료와 실제 원격 SHA의 ADR·절차·검증 문서를 연결한다. 로컬-only 결과는 해당 Jira에서 추적하며 존재하지 않는 원격 링크를 만들지 않는다. 원시 로그·비공개 원문·비밀값은 옮기지 않는다.
5. 페이지 본문·목차/상위 경로·근거 링크와 저장 결과를 재조회한다. 같은 사실을 여러 지식 문서에 복제하지 않고 연결한다. 내용과 적용 조건이 달라지면 기존 페이지를 다시 검토한다.
6. Jira·worklog에는 생성/갱신한 지식 페이지 링크 또는 미승격 이유만 요약한다. 작업 기록 갱신과 지식 문서화 완료를 별도로 보고하며, 저장 실패는 대기 상태로 남긴다.

이번에 정리한 지식 입구:

- [웹 현대화 판단: Baseline·타입·런타임](https://web-tech-service.atlassian.net/wiki/pages/19464193)
- [보안 업데이트: 패치·병합·배포·알림 해소](https://web-tech-service.atlassian.net/wiki/pages/19496961)
- [콘텐츠 캐시: 무효화와 최신 게시의 차이](https://web-tech-service.atlassian.net/wiki/pages/19234822)

이 기준은 매 작업을 수행하는 에이전트의 기록 의무다. 상시 자동 수집·예약 실행·공유 권한 변경을 설치하는 것은 아니며, 공통 지침의 main 전파는 커밋·PR·병합과 별개로 확인한다.

## 분류와 우선순위

앱 분류는 Jira Component가 아니라 라벨로 적용했다. 여러 앱에 걸친 작업은 라벨을 복수 사용한다.

| 라벨           | 범위                           |
| -------------- | ------------------------------ |
| `docs`         | 블로그 프론트·검색·콘텐츠 이용 |
| `docs-backend` | 콘텐츠 API·NAS 게시·푸시 저장  |
| `ui`           | 공용 UI·외부 소비·접근성       |
| `vuln-radar`   | 프론트와 백엔드의 서비스 과제  |
| `infra`        | CI·배포·보안 의존성·백업·관측  |

공통 라벨은 `web-tech`, 이번 이전 묶음은 `backlog-2026-10`이다. 우선순위는 `p1`·`p2`·`p0-gate` 라벨로 기록한다. 현재 작업 생성 필드에는 priority가 노출되지 않아 Jira 기본 Priority를 수정하지 않았다. `p0-gate`는 공개 활성화 전 필수 조건이며 현재 사고나 악용 관측을 뜻하지 않는다.

## 작업 생명주기와 완료

프로젝트의 현재 상태는 `해야 할 일 → 진행 중 → 검토 중 → 완료`다. 작업 시작과 실제 검토 시점에만 전환한다.

- 이슈에는 배경·현재 구현 상태·완료 조건·근거 문서·실행 제약을 기록한다.
- 버그는 재현 환경·순서·기대/실제 결과·회귀 검사까지 포함한다. 미검증 과제를 확인된 버그로 등록하지 않는다.
- PR 템플릿에 Jira 키/URL과 이번 PR에서 닫는 완료 조건을 적는다. 브랜치는 기존 [브랜치 정책](branch-policy.md), 커밋은 기존 [커밋 규칙](commit-message-convention.md)을 따른다.
- PR 제목·본문에는 담당자 실명·이메일·계정 식별자를 별도로 기재하지 않는다. 담당자 정보는 Jira에서 관리하며, PR에는 작업·검증 결과와 관련 링크만 남긴다. 이 규칙은 Jira 담당자 배정이나 GitHub 작성자·리뷰어 메타데이터를 변경하지 않으며, 필요한 원본 URL도 유지한다.
- 구현 완료·PR 병합·배포 성공·운영 검증은 다르다. 배포 검증 과제는 PR 병합만으로 완료하지 않는다.
- 완료 전 해당 커밋/배포 ID, 검사 명령과 관측 결과, 미검증 범위를 verification에 남기고 Jira에 연결한다.
- 이슈를 등록했다는 이유로 담당자·기한·스프린트를 지정하지 않는다.

## 매 작업의 최소 기록 절차

독립적으로 완료 여부를 판단할 수 있는 코드·설정·문서 변경, 배포·운영 조치와 검증을 작업 단위로 삼는다. 같은 목표의 작은 수정·재검사에는 기존 이슈와 Confluence 항목을 갱신한다. 설명만 요청한 대화나 도구 호출 한 번마다 새 이슈를 만들지는 않는다.

| 시점           | Jira                                                                                                                          | Confluence와 저장소                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 시작           | 제목·설명·라벨·추적 ID와 관련 PR을 검색한다. 없으면 작업을 만들고 범위·완료 조건을 명시한다. 착수할 때 진행 상태를 갱신한다.  | 기존 운영 안내나 관련 문서를 읽고 기록할 구역을 정한다. 현재 worklog에 Jira 키와 기존 Confluence 링크를 연결한다.            |
| 구현·검증      | 새로 확인한 결과·실패·차단 사유를 기존 설명/댓글에 반영한다. 검토가 시작되면 검토 중으로 전환한다.                            | 기술 결정·절차·실행 증거는 저장소 원본에 남긴다. 재사용할 개념·교훈은 Confluence 주제 문서로 승격하고, 진행 요약과 분리한다. |
| PR 생성·갱신   | PR URL, 커밋 SHA와 이번 PR이 충족하는 완료 조건을 연결한다.                                                                   | PR 본문에 Jira와 Confluence 링크를 모두 넣는다. 검증한 원격 커밋의 permalink를 사용하며, 로컬-only 변경은 별도로 표시한다.   |
| 작업 마감·보류 | 실행한 검사·결과·남은 검증·다음 행동과 지식 페이지 링크 또는 미승격 이유를 기록한다. 완료 조건이 남으면 완료로 바꾸지 않는다. | 작업 요약과 지식 문서를 각각 재조회한다. worklog·최종 보고에서 작업 기록, 지식 정리, 지침 반영 상태를 구분한다.              |

Confluence는 현재 [개발·운영 안내](https://web-tech-service.atlassian.net/wiki/spaces/~5d12f74be69c1c0c88af2afa/pages/65817/web-tech+Jira)의 관련 구역을 기본 입구로 사용한다. 짧은 후속 수정은 같은 구역을 갱신한다. 주제·분량·독자가 달라 별도 문서가 필요한 경우에만 새 페이지를 만들고 안내 페이지에 연결한다. 공간·공유 범위·외부 공개 권한은 이 절차로 변경하지 않는다.

마감 기록에는 목표와 실제 변경, PR/커밋/배포 식별자, 실행한 검사와 관측 결과, 미검증·보류 항목, 다음 행동을 포함한다. 로컬 초안의 본문·화면·원시 로그를 외부 도구에 올리지 않는다. 동일 Jira 설명·Confluence 항목을 재사용해 중복 댓글·페이지 생성을 줄인다.

### Jira 댓글 표준 형식

진행·검증·마감 댓글은 `항목 | 상태 | 결과 및 남은 작업` 3열 표를 기본으로 사용한다. 표 앞에는 기록 날짜와 작업 범위 또는 기준 커밋을 짧게 적는다. 다음은 항목 구성 예시이며 실제 수행 결과로 바꿔 작성한다.

| 항목      | 상태                  | 결과 및 남은 작업                                                                 |
| --------- | --------------------- | --------------------------------------------------------------------------------- |
| 변경 내용 | 진행 중 / 검토 중     | 변경 요약과 PR·커밋 링크. 로컬-only와 원격 반영을 구분한다.                       |
| 검증      | 통과 / 실패 / 미검증  | 실행 명령·조건·관측 결과와 검증한 SHA. 실행하지 않은 검사는 성공으로 적지 않는다. |
| 기록 연결 | 확인 완료 / 기록 대기 | Jira·Confluence·저장소 원본 링크와 실제 저장 확인 여부.                           |
| 남은 작업 | 대기 / 해당 없음      | 미병합·미배포·운영 미검증 등 남은 완료 조건과 다음 행동.                          |

- 한 셀에 긴 회고를 넣지 않는다. 상세 설명·원시 로그 대신 검증 문서와 커밋을 링크한다. 관련 없는 항목은 생략하고 배포·초안 보호 등 필요한 행만 추가한다.
- `로컬 반영`, `원격 반영`, `검토 중`, `대기`, `통과`, `실패`, `미검증`을 혼동하지 않는다. 이전 SHA의 CI 성공을 새 커밋의 결과처럼 쓰지 않는다.
- 같은 작업의 요약은 기존 댓글 ID를 확인해 갱신한다. 중요한 실패 이력·시점별 증거를 지우지 않으며, 새 댓글이 필요한 독립 사건도 같은 표 형식을 사용한다.
- 연결 도구의 지원 형식 안내를 먼저 확인하고 Jira가 실제 표로 저장하는 HTML 또는 네이티브 표를 사용한다. 기존 댓글의 링크·첨부·공개 범위를 보존하고, 저장 후 재조회해 표와 댓글 수를 확인한다. 표를 바꿨다는 이유만으로 이슈 상태를 완료로 바꾸지 않는다.

### 기록 실패와 권한 경계

- 응답이 모호하면 재조회한 뒤 복구한다. 쓰기가 실패했다고 같은 이슈나 페이지를 바로 다시 생성하지 않는다.
- 연결·권한·네트워크 오류로 기록할 수 없으면 worklog에 대상 이슈/페이지·미기록 요약·재시도할 항목을 남기고 최종 답변에 알린다. 미기록을 동기화 완료로 표시하지 않는다.
- Jira·Confluence 기록 의무는 승인되지 않은 배포·공개·PR 병합·초안 게시·자격 증명 변경을 허용하지 않는다. 안전하게 수행 가능한 로컬 작업과 외부 기록 실패를 구분한다.
- 작업자가 연결 도구로 수행하는 절차이며, 예약 작업·웹훅·자동 상태 전환·GitHub 앱을 이번 기준만으로 설치하거나 활성화하지 않는다.

보류는 이번에 새 workflow 상태를 만들지 않고 `on-hold` 라벨과 제목·설명으로 표시한다. Jira 상태는 `해야 할 일`에 유지한다. KAN-9는 NAS SSH 차단, KAN-10은 외부 백업 저장소 미구축이 사유다. 사용자 재개 승인 전 실행하지 않는다. 재개 시 라벨과 사유를 함께 갱신한다.

## 검색과 중복 방지

Jira 고급 검색에 아래 JQL을 사용한다. 앱 라벨을 바꾸면 다른 앱을 볼 수 있다.

```text
project = KAN AND labels = docs ORDER BY created DESC
project = KAN AND labels = p1 AND statusCategory != Done ORDER BY created ASC
project = KAN AND labels = "on-hold" ORDER BY key ASC
parent = KAN-1 ORDER BY key ASC
```

Jira의 기본 Priority는 위 라벨 우선순위와 다르므로 초기 목록을 `priority`로 정렬하지 않는다. 라벨별 저장 필터·대시보드는 아직 만들지 않았다.

새 등록 전 KAN의 이슈 제목·라벨·설명을 검색한다. 각 작업 설명 끝의 `web-tech:<주제>` 추적 ID를 비교한다. 생성 응답이 불명확하면 다시 검색한 뒤 복구하고, 즉시 재생성하지 않는다. 이 추적 ID 자체는 서버의 idempotency 보장이 아니다.

## 연결 범위와 후속 과제

Confluence 안내의 게시 여부·역할·링크를 갱신할 때는 저장된 페이지를 다시 읽어 확인한다. 현재 안내는 등록 시 확인한 GitHub 커밋의 문서 링크를 사용한다. 미커밋·미푸시 문서를 존재하는 원격 문서처럼 연결하지 않는다. 저장소 원본이 변경되어 안내의 의미가 달라지면 요약과 링크를 함께 갱신한다. 페이지는 기존 공간의 공개 범위와 권한을 따르며 별도 공개 공유를 켜지 않는다.

현재는 대화 도구를 통한 생성·조회와 PR 본문 수동 연결이다. GitHub for Atlassian 설치, 브랜치/PR 자동 연결, 머지 시 자동 전환, CI 실패 자동 티켓, 양방향 동기화는 미설정이다. Jira 이슈 키를 PR에 쓴 것만으로 자동 연결이 완료됐다고 표시하지 않는다.

공통 템플릿·정책의 main 반영은 사용자 승인 후 별도 커밋/PR로 진행한다. 전체 TODO를 일괄 이전하거나 외부 서비스를 자동 변경하지 않는다.
