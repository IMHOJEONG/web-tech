# 역할별 문서 템플릿

[문서 역할과 구조](documentation-organization.md)에 따라 위치를 고른 뒤 아래 형식을 사용합니다. 괄호 안내는 실제 내용으로 교체하고, 해당하지 않는 항목은 이유와 함께 해당 없음으로 표시합니다. 기존 문서를 단지 형식 때문에 일괄 재작성하지는 않습니다.

## 설계와 정책

위치: `docs/architecture/주제.md`

```markdown
# 정책 또는 설계 제목

## 상태와 범위

- 상태: 제안
- 대상: docs 앱
- 최종 검토: YYYY-MM-DD

상태는 제안 / 적용 중 / 보류 / 폐기 중 선택. 검토일은 실제 검토 날짜로 교체.

## 배경

해결하려는 문제와 제약.

## 결정

선택한 구조와 책임 경계.

## 대안과 영향

대안별 장단점, 선택 이유, 위험 및 되돌릴 조건.

## 관련 문서

구현 기록, 운영 절차, 검증 결과 링크.
```

## ADR

구조적으로 중요한 결정 하나를 기록할 때는 [ADR 관리 규칙](adr-management.md)을 먼저 확인합니다. 위치: `docs/architecture/adr-NNNN-주제.md`.

```markdown
# ADR-NNNN: 결정 제목

## 상태와 범위

- 상태: 제안
- 대상: 앱 또는 공통 패키지
- 결정일: YYYY-MM-DD
- 최종 검토: YYYY-MM-DD
- 대체: 이전 ADR 링크(해당할 때만)

## 배경

결정을 요구한 문제와 제약.

## 결정

선택한 방향과 책임 경계. 제안 상태라면 아직 적용되지 않았음을 명시.

## 대안과 영향

검토한 다른 방향, 장단점, 재검토 조건.

## 관련 문서

현재 정책, 구현 worklog, 검증 링크.
```

ADR의 결정일과 검토일은 실제 확인한 날짜를 사용합니다. 이전 ADR을 대체했다는 사실은 새 문서와 이전 문서에 모두 연결합니다.

## 운영과 재현 절차

위치: `docs/runbooks/주제.md`

```markdown
# 절차 제목

## 목적과 준비 조건

대상 환경, 권한, 도구 버전. 비밀값 대신 환경 변수 이름만 기재.

## 실행 순서

실행 디렉터리, 명령, 변경 영향 및 필요한 승인.

## 기대 결과

성공 여부를 판단할 응답과 확인 방법.

## 실패 대응과 복구

중단 조건, 조사 순서, 되돌리는 방법.

## 관련 검증

특정 날짜의 결과는 verification 보고서로 연결.
```

## 검증 보고서

위치: `docs/verification/주제/YYYY-MM-DD-대상.md`

```markdown
# 검증 제목

## 대상과 조건

검증 날짜와 시간대, 커밋/배포, 환경, 도구 버전, 표본 수.

## 재현 방법

준비 조건, 실행 디렉터리와 실제 실행 명령.

## 결과와 증거

기대 조건, 실제 관측값, 통과 / 실패 / 미검증 구분.
원본 artifact 상대 링크. 실행하지 않은 항목은 성공으로 표시하지 않음.

## 한계와 후속 작업

통제하지 못한 조건과 결과를 일반화할 수 없는 범위.

## 관련 문서

정책, runbook, 수정 worklog 링크.
```

## 작업 기록

위치: `docs/worklog/YYYY-MM/YYYY-MM-DD-주제.md`

```markdown
# 작업 제목

## Summary

이번 작업의 목적과 결과.

## Changed

변경 범위와 관련 문서 링크.

## Notes

수행한 검사, 제약, 미검증 사항. 긴 측정 결과는 verification으로 연결.

## Open Questions

남은 판단 사항. 없으면 없음.

## Next

다음 작업과 완료 조건. 없으면 없음.
```

## 지식과 후속 계획

- `docs/knowledge/`: 개념 → 프로젝트에서 배운 점 → 적용 조건과 주의점 → 관련 정책/절차 순으로 정리합니다.
- `docs/todo/`: 기존 목록에 우선순위, 할 일, 완료 조건, 근거 링크를 추가합니다. 같은 작업의 TODO 파일을 중복 생성하지 않습니다.
- `docs/verification/artifacts/`: 보고서에서 참조하는 날짜·주제별 결과 데이터만 저장합니다. 원본을 변조하지 않고 민감정보는 저장 전에 제거합니다.

## 추가 완료 체크

검사 범위와 실행 명령은 [문서 품질 검사](documentation-quality-gates.md)를 참고합니다.

- [ ] 기존 문서와 중복되지 않는 위치 및 역할인가?
- [ ] 대상 앱, 현재 적용 상태, 미검증 사항이 분명한가?
- [ ] 역할별 README와 작업 월의 목차를 갱신했는가?
- [ ] 새 문서 및 관련 문서의 상대 링크가 실제 파일을 가리키는가?
- [ ] 비밀정보를 제외했으며 결과·절차를 중복 복사하지 않았는가?
