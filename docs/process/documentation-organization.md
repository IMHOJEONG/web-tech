# 문서 역할과 구조

## 분류 원칙

새 문서를 만들거나 기존 문서를 확장할 때 [역할별 문서 템플릿](documentation-templates.md)을 사용하고 추가 완료 체크를 수행합니다. 저장소 루트 `AGENTS.md`에서도 이 규칙을 참조합니다.

문서의 주된 질문으로 위치를 결정합니다. 프로젝트별 새 문서 트리를 중복 생성하지 않고 역할을 먼저 구분하며, 제목과 파일명으로 대상 앱을 명확히 합니다.

| 역할           | 경로                           | 필수 내용                                  |
| -------------- | ------------------------------ | ------------------------------------------ |
| 설계·정책      | `docs/architecture/`           | 배경, 결정, 대안, 영향, 현재 적용 여부     |
| 운영·재현 절차 | `docs/runbooks/`               | 준비 조건, 명령, 기대 결과, 실패 대응      |
| 검증 결과      | `docs/verification/<주제>/`    | 날짜, 커밋/배포, 환경, 명령, 결과, 한계    |
| 검증 증거      | `docs/verification/artifacts/` | 해당 보고서에서 설명하는 원본 측정값       |
| 작업 이력      | `docs/worklog/YYYY-MM/`        | 변경 요약, 연결 문서, 열린 문제, 다음 작업 |
| 재사용 지식    | `docs/knowledge/`              | 개념, 반복되는 교훈, 관련 정책/절차 링크   |
| 후속 계획      | `docs/todo/`                   | 우선순위, 완료 조건, 관련 근거             |

## 검증과 작업 기록 구분

테스트 도입이나 수정 내용을 설명하는 글은 worklog입니다. 어떤 버전에서 어떤 조건으로 실행했고 무엇이 통과/실패했는지 증명하는 글은 verification입니다. 실패하거나 미완료인 검증도 결과를 숨기지 않고 같은 위치에 둡니다.

주제 폴더는 현재 `performance`와 `cache`를 사용합니다. 검증 보고서가 실제로 생겼을 때만 새로운 주제 폴더를 추가합니다. `artifacts`는 실행 결과 데이터 전용입니다.

검증 보고서 형식:

1. 대상 날짜, 커밋 또는 배포 식별자.
2. 환경, 측정 조건, 도구 버전.
3. 저장소 루트에서 실행할 명령과 선행 조건.
4. 기대 조건과 실제 결과. 통과·실패·미검증 구분.
5. 관련 artifact 상대 링크 및 판단 근거.
6. 표본 수, 통제하지 못한 조건, 후속 검증.

## 중복 방지

- runbook에는 반복할 절차를 유지하고 특정 날짜의 긴 결과표는 검증 보고서에 둡니다.
- worklog는 보고서를 링크합니다. 이미 보고서가 있는 경우 전체 결과를 다시 복제하지 않습니다.
- 기존 worklog 안의 짧은 테스트 결과를 모두 별도 파일로 쪼개지는 않습니다.
- 기존 보고서의 날짜·조건·실패 결과는 재분류 과정에서 변경하지 않습니다.
- artifact 파일 이름에는 측정 날짜와 주제를 포함하고 비밀정보를 제거합니다.

## 탐색과 이동

목차는 수동 설명을 보존하고 [변경 문서 검사](documentation-quality-gates.md)로 누락을 확인합니다. 개수는 쉽게 낡으므로 목차에 수동 집계 숫자를 새로 추가하지 않습니다.

- 루트 README는 역할별 입구, 하위 README는 해당 역할의 문서 목록입니다.
- 새 문서 추가 시 해당 역할의 목차도 함께 갱신합니다. 작업 기록은 월별 목차에 추가합니다.
- 문서를 이동할 때 저장소 전체의 명시적 경로와 이동 문서 내부 상대 링크를 함께 갱신합니다.
- 이동 전부터 깨진 링크와 이동으로 새로 깨진 링크를 구분하여 검증합니다.
- 저장소 내부 참조는 갱신하지만 외부에 공유된 GitHub blob URL은 자동으로 리디렉션되지 않습니다. 기존 커밋의 permalink를 사용하거나 새 위치를 안내합니다.

## 2026-09-19 정리 범위

검증 중심 보고서 5개를 분리하고 artifact 6개를 이동했습니다. 작업 기록 166개는 원문을 유지한 채 월별 분류했습니다. 설계·운영 문서는 기존 경로를 유지하여 참조 변경을 최소화하고 목차를 추가했습니다. 블로그 글, 애플리케이션 동작, 배포 설정은 변경하지 않습니다.
