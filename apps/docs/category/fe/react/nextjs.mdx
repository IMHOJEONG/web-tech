## Next.js 패키지를 살펴보는 이유

- 프레임워크를 사용할 때는 공개 API만 알아도 기능을 만들 수 있다.

- 다만 빌드 결과, 서버 렌더링, 라우팅 동작을 디버깅하려면 패키지 내부 구조를 어느 정도 이해하는 편이 좋다.

- 특히 Next.js는 React, 번들러, 서버 런타임이 맞물려 있어서 문제가 생겼을 때 원인을 한 계층에서만 찾기 어렵다.

### 먼저 확인할 영역

- `next` 패키지가 앱 라우터와 페이지 라우터를 어떻게 나누어 제공하는지 본다.

- 서버 렌더링 템플릿과 런타임 코드가 빌드 결과에 어떤 형태로 포함되는지 확인한다.

- 개발 서버와 프로덕션 빌드에서 사용하는 모듈 로딩 방식이 어떻게 달라지는지 비교한다.

## 읽을 때의 기준

- 내부 구현을 외워두기보다, 에러 메시지가 어느 계층에서 발생했는지 추적할 수 있는 정도를 목표로 둔다.

- 문서화된 API와 내부 파일 경계를 구분해서, 내부 구조에 직접 의존하는 코드는 만들지 않는다.
